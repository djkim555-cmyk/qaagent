## 0. 정렬 / 에스컬레이션 (팀장 컨펌 전제)

확정된 결정(운영자):

- **동기화 방향**: 단방향(읽기) 아님 → **양방향**. 단, 전체 양방향이 아니라 **데이터 성격별 분할**(§2, §4).

## 1. 배경 · 문제 · 목표

**문제.** `webapp`은 로컬 PC 단일 프로세스(Express + node:sqlite + Agent SDK + Playwright)다. 터널을 붙여도 **PC가 깨어 있을 때만** 접속되고, 동료가 결과를 보거나 **트리아지(담당자 배정·상태 변경)에 참여할 수 없다.**

**핵심 통찰 — 데이터 성격이 두 갈래.**
- **실행 데이터**(무거움·로컬 전용 생성): 페르소나가 Chromium·LLM 구동으로 만든 결과. **클라우드는 못 만들고, 고치지도 않음.**
- **트리아지/주석 데이터**(가벼움·양쪽 편집): 이슈 담당자·상태·메모, 프로젝트 숨김 등. **로컬·클라우드 어디서든 편집 가능해야 가치.**

**목표.** 실행 엔진은 로컬에 두되,
1. 결과 조회를 클라우드에서 24/7(=v0.1 목표), **그리고**
2. 트리아지 레이어를 **양방향 동기화**해 PC 없이도 동료가 분류·배정에 참여, 로컬은 그 변경을 흡수.

**비목표(이번 MVP).** 클라우드에서의 QA 실행/재실행, 페르소나·시나리오 편집, 리포트 본문 편집.

## 2. 데이터 분할 — 충돌 면적 최소화 (설계의 핵심)

| 구분 | 테이블·필드 | 생성·소유 | 동기화 방향 | 충돌 |
|---|---|---|---|---|
| **A. 실행 데이터** | `runs`, `persona_runs`, `issues`의 본문(title·severity·symptom·repro·evidence…), 리포트·스크린샷 파일 | 로컬 전용 | **로컬 → 클라우드 (단방향 복제)** | **없음** |
| **B. 트리아지 레이어** | `issues`의 `assignee_id`·`status`·`memo`·`category`, `projects.hidden`, `project_members`, `developers` | 양쪽 | **양방향 (LWW)** | 드묾 → §4 |
| **C. 신원/비밀** | `managers.password_hash`, env | 로컬 | **미동기화** | — |

> 즉 "완전 양방향"이 아니라 **A=단방향 + B=양방향(작은 표면) + C=차단**. 이래서 풀 멀티마스터 엔진 없이도 실질 양방향이 된다.

## 3. 아키텍처 (C안)

```
┌─ 로컬 PC (실행기 · 트리아지 가능 · SoT of A) ─┐        ┌─ Cloudflare (24/7 · 트리아지 가능) ─────────┐
│ 페르소나 QA 실행 → 로컬 qa.db + reports 파일   │  push  │  Workers(Hono): 조회 + 트리아지 쓰기 API     │
│ 동기화엔진:                                    │ ─────▶ │     │                                        │
│   · A 데이터 push (run 종료 시)                │        │   D1: 복제본(A 읽기) + 트리아지(B 원장)      │
│   · B 변경 push + 클라우드 B 변경 pull(LWW)    │ ◀────▶ │   R2: 리포트 MD + 스크린샷                    │
└────────────────────────────────────────────────┘  pull  └──────────────────────────────────────────────┘
```

- 무료 티어(D1 5GB·5M reads/day, Workers 10만 req/day, R2 10GB·egress 0) → 사내 규모 비용 ≈ 0.
- 코드가 D1 이전 전제로 설계됨(`db.ts`: "SQLite 방언이라 D1 이전 시 SQL 재사용") → 스키마 이식 용이.

**철회 조건.** 트리아지 동시편집 충돌이 빈번해지거나 풀 양방향(실행 데이터까지)이 필요해지면 → CRDT/전용 sync 백엔드 또는 상시 서버(B안) 재검토.

## 4. 동기화 계약 — **양방향 (D1·D4 결정)**

### 4.1 모델
- **A 데이터**: run 종료 시 로컬→클라우드 **멱등 upsert**(run id PK). 클라우드는 읽기만. 충돌 없음.
- **B 데이터**: 양방향. 각 동기화 대상 행에 **`updated_at`(epoch ms) + `updated_by`(이메일/‘local-admin’) + `deleted`(툼스톤)** 부여.
- **충돌 해소**: **행단위 LWW** — 동기화 시 양쪽 같은 행이면 `updated_at` 큰 쪽 채택. 같으면 클라우드 우선(항상 켜져 있어 기준 시계로 신뢰).

### 4.2 흐름 (로컬이 간헐 접속 클라이언트)
로컬이 온라인이 될 때마다(그리고 주기적으로, 그리고 "지금 동기화" 버튼):
1. **Push A**: 미발행 run을 `POST /ingest/run`(토큰)으로 → D1 upsert + 파일 R2 PUT.
2. **Push B**: 마지막 동기화 이후 로컬에서 바뀐 B행을 `POST /sync/triage`(토큰)로 → D1가 LWW 적용.
3. **Pull B**: `GET /sync/triage?since={cursor}` → 클라우드에서 바뀐 B행 수신 → 로컬 LWW 적용.
4. **커서 갱신**: 로컬에 `last_sync_at` 저장(워터마크). 클라우드도 행별 `updated_at`로 델타 산출.

### 4.3 멱등성·삭제·순서
- 모든 쓰기는 자연키 upsert → 재시도/중복 안전.
- 삭제는 물리삭제 대신 `deleted=1` 툼스톤으로 전파(양쪽 일관). 영구 정리는 보존정책에서 별도.
- 시계 오차 완화: 클라우드 쓰기는 D1 서버시간 스탬프, 로컬 쓰기는 로컬시간 스탬프 → LWW 오차는 트리아지 저빈도라 허용(최악=메모 1건 덮어쓰기, 복구 가능).

### 4.4 보안
- `INGEST_TOKEN`/`SYNC_TOKEN`은 `wrangler secret` + 로컬 `.env`만. 뷰어 사용자에 미노출.
- C(비밀) 절대 미동기화.

```
온라인 전이 ─▶ [1 push A] ─▶ [2 push B] ─▶ [3 pull B] ─▶ last_sync_at 갱신
                    └ run 종료 이벤트로도 1 트리거
```

## 5. 뷰어 범위 — 읽기 + 트리아지 쓰기

기존 ViewLogic 뷰 재활용. MVP 화면:
1. 프로젝트 목록 / 2. 프로젝트 상세(run 리스트) / 3. 실행 상세(페르소나별 + 통합 리포트 R2 렌더) / 4. 이슈 상세(증거 스크린샷).
- **읽기**: A 데이터 전부.
- **쓰기(트리아지만)**: 이슈 상세에서 담당자(`assignee_id`)·상태(`status`)·메모(`memo`)·분류(`category`) 편집, 프로젝트 숨김. 저장 시 D1에 `updated_at=now, updated_by=이메일` 기록(→ 로컬이 pull).
- **제외**: 실행 트리거, 리포트/이슈 본문 편집, 페르소나·시나리오 편집, 회원 비밀번호.

## 6. 인증 — **Cloudflare Access (D2)**

- 뷰어 앞단을 Access로 감싸 **허용 이메일만** 도달. 앱 인증 로직 0, `password_hash` 미동기화.
- **이메일 = 트리아지 편집자 신원**(`updated_by`) → 누가 바꿨는지 감사 가능. "각자 계정으로 본다 + 누가 분류했는지 남는다"를 동시에 충족.
- 프로젝트별 세분 접근은 2차(이메일↔`project_members` 매핑). MVP는 허용목록 전원 전체 열람·트리아지.

## 9. 작업 분해(WBS) · 위임 · 마일스톤

**M0 — 스키마 준비(로컬, 오현우)**: B 테이블에 `updated_at`/`updated_by`/`deleted` 컬럼 보강(`db.ts` 경량 마이그레이션 패턴). 로컬에 `last_sync_at` 커서 저장소.
**M1 — 기반(배준호/devops)**: Cloudflare 계정·wrangler·D1 생성·R2 버킷·`db.ts` DDL→D1 마이그레이션·Access 설정.
**M2 — 동기화엔진(오현우/backend)**: 로컬 push/pull 모듈(A push, B 양방향 LWW), Worker `/ingest/run`·`/sync/triage`(토큰·upsert·LWW), R2 업로드. `[→ 오현우]`
**M3 — 뷰어(정시우/frontend + 곽민서/publisher)**: 읽기 화면 4종 + 이슈 트리아지 편집 UI(D1 쓰기). `[→ 정시우]`
**M4 — 검증(신유진/proj-qa + 차은성/security)**: 동기화 멱등성·LWW·툼스톤·동시편집 시나리오 테스트, 토큰/PII 보안. 종료조건: 심각도 '상' 0건 + 팀장 컨펌.

> 권고 순서: M0 → M1 → (M2 ∥ M3, **API 계약 먼저 고정**) → M4. 사내 "API 계약 우선" 적용 — `/ingest/run`·`/sync/triage`·뷰어 조회 형태를 **06_API계약서**로 먼저 박는다.

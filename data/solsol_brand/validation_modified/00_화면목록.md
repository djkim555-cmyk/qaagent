## 1. 화면ID(Screen ID) 체계 — 필수

사내 표준 `DOCS-화면설계서작성표준.md` §2를 따른다.

**형식**: `S-[업무구분코드]-[Depth]-[화면번호][팝업구분]`
**예시**: `S-FR01-010102-001P01`

| 토큰 | 의미 | 규칙 |
|------|------|------|
| `S` | 화면설계서 고정코드 | 항상 `S` |
| `[업무구분코드]` | 영역(업무) 구분 | 아래 표 참조 (`FR01`/`AD01`/`BR01`) |
| `[Depth]` | 메뉴 계층 경로 | 2자리씩 메뉴 depth를 누적(예: `0101`=1depth 01 > 2depth 01) |
| `[화면번호]` | 화면 일련번호 | 3자리(`001`부터) |
| `[팝업구분]` | 해당 화면 내 팝업 | `P01`, `P02` … (없으면 생략) |

### 업무구분코드 (영역) 정의

| 코드 | 영역 | 설명 | 화면설계서 파일 | 캡처 폴더 |
|------|------|------|----------------|-----------|
| `FR01` | Customer Front | 수강생/고객용 학습 프론트 | `01_customer-front.md` | `screenshots/customer-front/` |
| `AD01` | Customer Admin | 고객(운영자/강사)용 관리자 | `02_customer-admin.md` | `screenshots/customer-admin/` |
| `BR01` | Brand site | 브랜드/마케팅 사이트 | `03_brand-site.md` | `screenshots/brand-site/` |

### 부여 규칙 (사내 표준 + DJ 지시 오버라이드 2026-06-25)

> **DJ 컨펌(2026-06-25)**: 모달·팝업도 각각 독립 '화면'으로 인식해 화면ID를 부여하고 본수에 합산한다. 사내표준 §2 'MPU ID 미부여'를 본 지시로 **오버라이드**한다(단, 범용 Alert/Confirm·토스트는 공통 컴포넌트로 1회만 — 개별 카운트 제외).

- **모달/팝업 네이밍 = `부모화면ID_pu##`** (모달·팝업·LPU·PU·BS 전부 동일 형식). 부모 화면 내 등장 순서대로 `_pu01, _pu02 …`. 기존 `P01/P02` 표기는 곧 `_pu01/_pu02`로 1:1 매핑(외부·범용 제외분 정정 시 등장순 재순번).
- **카운트 대상 = 고유 콘텐츠를 가진 모달·팝업·LPU·PU·BS**. 각각 1페이지로 카운트.
- **카운트 제외**: ① **범용 Alert/Confirm**(콘텐츠 없는 단순 경고·확인창 — "삭제하시겠습니까?" 류, 해제/취소/카드삭제 컨펌, 결과 통보형 안내) ② **토스트**(전부) ③ **외부 시스템 모달**(toss 카드등록·영수증, NICE/PASS 본인확인, 카카오/페이스북/OS 공유·파일선택 — 우리 설계대상 아님) ④ **모바일 반응형 변형 BS**(PC 기능을 모바일에서 BS로 띄우는 필터/정렬/더보기/메뉴 변형 — 본화면 종속).
- **공유 모달 컴포넌트**(여러 부모화면이 재사용하는 콘텐츠형 LPU)는 **컴포넌트로 1회만 ID 부여(`S-{영역}-C##`)·1회 카운트** — 사용 화면마다 중복 카운트 금지. 범용 C-모달/얼럿/컨펌/토스트는 제외.
- 화면ID는 **단계 간 추적 키**다 — `00_화면목록` ↔ `01~03 화면설계서` ↔ `04_정책요약`에서 동일 ID로 1:1 매핑(누락 0). 각 `_pu`행은 **근거(부모 pXXX 또는 본문 위치)** 필수(추정·날조 0).

## 2. UI / DEV 타입 범례 (표 작성용)

- **UI TYPE**: `P`(전체화면,[이전]) · `PU`(전체팝업,[닫기]) · `LPU`(레이어 팝업) · `MPU`(Alert/Confirm 모달) · `BS`(바텀시트).

- 표의 `UI/DEV타입` 컬럼은 `P / W` 형식으로 함께 표기.

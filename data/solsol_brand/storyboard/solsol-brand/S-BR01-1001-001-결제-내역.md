# [S-BR01-1001-001] 결제 내역
> route: /my/payments · 정리: 나래님 · 최종수정 2026-07-27 (KST) · 상태: 작성완료

## 기능 정의
- 결제 내역 목록. 데이터 유무에 따라 `#pay-data`(표) ↔ `#pay-empty`("아직 결제 내역이 없네요!") 분기.
- 필터바: 기간(전체/최근 1·3·6개월/1년) · 결제상태(전체/결제완료/결제취소) · 지급수단(전체/신용카드/체크카드) 3종 커스텀 셀렉트로 표를 실제 필터링. 선택 시 `solsol:select` 이벤트 발행 → 페이지 `apply()` 재필터.
- 검색: 검색어 Enter 또는 돋보기 클릭 시에만 표 행(`tr[data-search-item]`) 텍스트 매칭 필터, × 로 초기화(공통 규칙 P1, [common.md](../../policy/brand/common/common.md) §목록 검색).
- 초기화(`.btn-circle`): 필터바 셀렉트 전체 첫 옵션 복귀 + 검색어 초기화(공통 P4).

## 표시 조건 · 상태·분기
- 결제 내역 0건 → 빈 상태(`#pay-empty`).
- 필터·검색 조건에 맞는 행 0건 → "조건에 맞는 결제 내역이 없어요!"(검색 중이면 "검색 결과가 없어요!")로 문구 분기.

## 정책 (변경 사항 · 값·수치)
- 정본: [`docs/policy/brand/front/payments.md`](../../policy/brand/front/payments.md) — 기간 필터는 [미확정] 실제 로직(목업은 표시용, 데이터가 동일 날짜라 필터 효과 없음).
- 실연동 시 표 검색·필터는 서버 쿼리(기간·상태·수단·검색어) 파라미터화 필요 — 계약 정본 = brand-api `/doc`.

## 이식 주의 종합
- **최우선(2건, 둘 다 상)**: ① 검색 실시간 필터(D01) ② 결제상태 필터 키보드 접근 불가(신규 접근성 발견) — 같은 패턴이 문의 내역 목록(`S-BR01-0702-001`)에도 있는 D01과, 커스텀 셀렉트 공통 컴포넌트 개편 시 함께 처리하면 효율적.
- 필터바 3종 복원 시 지급수단 옵션은 서버 계약(brand-api 결제수단 enum)과 맞춰야 함 — 계약 확인 필요.
- 검색·필터 클라이언트 텍스트 매칭은 목업 방식 — 실연동 시 서버 쿼리 파라미터화(기간·상태·수단·검색어) 필요.
- **접근성 심층 검토(2026-07-27 3차 QA)**: 위 필터 키보드 접근 불가 외에도 모달 11종의 포커스 트랩·복귀 부재, 폼 6개의 필드별 에러 스크린리더 미전달 등 앱 전반의 접근성 결함이 별도로 확인됨 — 상세는 `docs/dev-validation/spike/_storyboard-qa3-a11y.md` 참조(이 화면 범위 밖이라 여기 전문 반영은 생략).

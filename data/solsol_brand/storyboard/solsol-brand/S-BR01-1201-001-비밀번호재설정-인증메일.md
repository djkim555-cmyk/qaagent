# [S-BR01-1201-001] 비밀번호 재설정 인증 메일
> route: 해당 없음(서버 발송 트리거 — brand-api 이벤트) · 정리: 새롬님 · 최종수정 2026-07-27 (KST) · 상태: 작성완료

## 기능 정의
- 비밀번호 재설정 요청(`/password-reset`) 시 발송되는 HTML 이메일(`auth/password-reset-email.html`).
- 구성: 로고 헤더(다크) + "비밀번호 재설정을 위한 인증 안내입니다" 타이틀 + 안내문 + **[비밀번호 재설정 하기] CTA 버튼**(클릭 시 `/password-reset-new`로 이동) + 유효시간 안내 박스(mockup2 원본 표기는 "보안을 위해 본 링크는 발송 후 1시간 동안만 유효합니다" — **단 이 값은 확정 정책과 다름, 아래 정책 섹션 참조**) + URL 복사 안내(버튼 클릭 불가 시 대비) + 보안 안내(3개 불릿) + 발신전용 푸터.
- 링크는 토큰 쿼리스트링 포함(`?token=...&expires=...`) — 목업 예시는 더미 JWT.

## 표시 조건 · 상태·분기
- 해당 없음(사용자가 화면으로 진입하는 개념이 아니라 서버 이벤트 발송).

## 정책 (변경 사항 · 값·수치)
- **⚠️ 정책 충돌(2026-07-27 storyboard 2차 QA 발견 — 정정)**: mockup2 원본은 "1시간"으로 표기하나, 상위 정본 `docs/validation/05_정책설계서.md` §C-2가 이미 **"비밀번호 재설정 링크/코드: Brand 1시간 → 30분으로 하향 통일"**을 확정했다(회원가입 인증코드 3분→10분과 짝을 이루는 결정, 근거: 재설정 링크는 탈취 시 계정 takeover 위험이라 짧을수록 안전). **값·수치(확정) = 30분**. mockup2·본 문서 초안이 구값(1시간)을 그대로 인용한 것이 오류였음 — 이식 시 30분 기준으로 구현.
- **오너 확인 필요(외부 발신)**: 이메일 발송은 비가역·외부 공개 영향. brand-api 발송 게이트웨이 미확정 — `solsol-brand-api/src/routes/auth.ts:727` `TODO(mail): 재설정 링크 발송` 주석 잔존(현재는 토큰 발급만 동작, 실 메일 미발송).
- 변수 치환 설계 **[미확정]**: 목업2는 정적 HTML이라 토큰·만료시각 등 변수 치환 방식은 brand-api 발송 게이트웨이 확정 시 별도 설계 필요.
- **UX 판단(2026-07-27 3차 UX 후속검증, 2차 QA 백로그 해소)**: 30분은 재설정 링크가 이메일을 열람하기까지 걸리는 현실적 지연(알림 확인·다른 기기 전환 등)을 감안하면 사용자가 놓치기 쉬운 극단적으로 짧은 값은 아니면서도, 링크는 클릭 한 번으로 인증이 끝나는 형태라 탈취 시 위험이 코드 입력형보다 크다 — 그래서 회원가입 인증코드(10분)보다 짧게 잡은 것이 보안·사용성 균형상 타당하다. 가입 인증코드(3분→10분 상향)와 짝지어 보면 "탈취 위험이 큰 링크형은 짧게, 낮은 코드형은 여유 있게"라는 일관된 원칙이 확인된다.

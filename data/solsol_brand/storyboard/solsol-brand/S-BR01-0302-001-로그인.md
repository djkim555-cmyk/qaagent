# [S-BR01-0302-001] 로그인
> route: /login · 정리: 나래님 · 최종수정 2026-07-27 (KST) · 상태: 작성완료

## 기능 정의
- 이메일·비밀번호 로그인. `useAuth().login()` → BFF `POST /api/session/login` → brand-api `POST /api/auth/login`.
- 계정 열거 방지를 위해 이메일/비밀번호 실패를 구분하지 않는 단일 실패 메시지.
- `?next=`로 전달된 원 목적지(보호라우트 게이트가 붙임)로 로그인 성공 시 이동, 없으면 `/my/sites`.
- 임시 검수용 로그인 버튼(리뷰어별 계정 10개, accepted-risk, 오너 승인 2026-07-16) — 폼 제출과 완전히 동일한 `doLogin` 함수를 호출한다(실제 BFF·brand-api를 그대로 타는 것으로, mock/우회 아님). 자격값은 `NUXT_PUBLIC_REVIEW_ACCOUNTS`(배포 시점 env 배열 주입)로만 존재, 소스 리터럴 없음.

## 표시 조건 · 상태·분기
- **로그인 상태에서 `/login` 접근 시 즉시 `/my/sites`(또는 안전한 내부 `next`)로 리다이렉트**(2026-07-16, 오너 지시) — `app/middleware/01.require-auth.global.ts`의 `GUEST_ONLY_EXACT` 게이트, "인증됨 + `/login`" 조합에서만 발동. 비로그인 정상 접근·`?next=` 플로우는 그대로 유지.
- 검수용 로그인 버튼 섹션은 `NUXT_PUBLIC_SHOW_TEST_LOGIN` 빌드타임 값이 켜진 빌드에서만 렌더(기본값 OFF). `NUXT_PUBLIC_REVIEW_ACCOUNTS` 배열이 비어 있으면 섹션 자체가 렌더되지 않는다.

## 정책 (변경 사항 · 값·수치)
- 로그인 게스트 전용 게이트 신규(2026-07-16, 오너 지시).
- 검수용 로그인 10계정 — **오너 확인(계정/보안)**. 자격 주입은 배포 시점 env 배열 방식(`NUXT_PUBLIC_REVIEW_ACCOUNTS`), git 이력·소스에 리터럴 없음. **GA(정식 오픈) 전 반드시 OFF 빌드로 재배포**(배포 담당자 체크리스트 항목).

## 이식 주의 종합
- 계정 열거 방지를 위한 단일 실패 메시지 문구는 실연동 이후에도 그대로 유지할 것.
- `?next=` 플로우와 게스트 전용 게이트(`GUEST_ONLY_EXACT`)의 상호작용을 실연동 시에도 유지 — `/signup` 등 다른 게스트 페이지는 이 게이트 범위 밖.
- D10(오픈리다이렉트 심층방어 가드)은 blocker 아님, 후속 백로그로 관리.
- 검수용 로그인 버튼은 GA 전 반드시 OFF 빌드로 재배포 — 실 고객 프로덕션에는 노출되어서는 안 됨.

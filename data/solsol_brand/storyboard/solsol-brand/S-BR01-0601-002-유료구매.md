# [S-BR01-0601-002] 유료 구매
> route: /purchase · 정리: 나래님 · 최종수정 2026-07-27 (KST) · 상태: 작성완료

## 기능 정의
- 선택된 플랜의 결제 화면. 좌측 "선택된 플랜" 요약 카드(플랜명·배지·플랫폼 수수료·구독 주기·구독 기간(예상)·다음 결제일·결제 예정 금액)와 우측 "결제하기" 카드(카드 등록 여부·구독서비스 결제 안내·약관 동의·결제 버튼)로 구성.
- 쿼리 파라미터: `siteId`(필수 — 구독을 연결할 내 사이트), `planId`(선택, 없으면 플랜탭에서 고름), `cycle`(`m`|`y`, 기본 `m`).
- `GET /api/plans`·`GET /api/sites`로 실데이터 로드, 플랜탭에서 구매할 플랜 선택 → 월간/연간 토글 → 결제 예정 금액 갱신.
- 결제 버튼은 카드 선택 완료 + 약관 동의 시 활성화. 클릭 시 `POST /api/subscriptions`(⚠️게이트) 호출 → 성공 시 `/purchase-complete?subscriptionId=…`, 실패 시 `/purchase-failed?reason=…`으로 이동.
- "구독 기간(예상)"은 결제 전 클라이언트 계산 예상치이며 실 시작일은 결제 승인 시점에 서버가 확정 — `MockBadge`로 실데이터가 아님을 명시.

## 표시 조건 · 상태·분기
- `GET /api/plans`·`GET /api/sites` 로딩 중=loading, 실패=error(재시도), 대상 사이트 없음=empty("내 사이트 관리하기"로 유도), 구매 가능한 플랜 0건=empty.
- 결제 버튼 비활성 조건: 카드 미선택 또는 약관 미동의. 카드 미선택 시 "결제 정보 등록은 필수입니다" 에러 노출. 약관 미동의 상태에서 제출 시도 시 "약관 동의는 필수입니다" 에러 노출.
- 실 토스 카드 승인은 staging-gate라 `POST` 응답이 항상 `sub_state=pending`으로 생성 — 성공해도 "결제 완료"라 단정하지 않고, `/purchase-complete`가 `subState`로 문구를 분기한다(무음 성공 위장 금지).

- 목업2 원본(약관 미동의 시 결제하기 비활성) 로직 유지, 카드 등록 강제는 실연동에서 `CheckoutCardBox`(카드 선택 컴포넌트)로 대체됨.

## 이식 주의 종합
- **`/purchase` 진입점 배선이 최우선 과제** — 가격 페이지(`pricing.vue:207`)의 유료 CTA가 `/login?next=/my/sites`로 우회하고 있어(로그인 게이트를 거쳐 `/my/sites`로 감 — 단순 `/my/sites` 직행이 아님) 이 화면으로 오는 정상 경로가 없다. 이식·재검증 시 가격 페이지 CTA 수정과 세트로 처리할 것.
- 결제 결과(완료/실패) 라운드로빈은 목업 한정 로직 — 실연동은 이미 API 응답 분기로 대체됨(구현 완료 확인).
- 카드 등록 완료 여부는 실연동에서 `CheckoutCardBox`가 담당, 토스페이먼츠 실 카드 인증은 스테이징 게이트로 비활성.
- **D18 카피 변경 UX 판단(2026-07-27 3차 UX 후속검증, 2차 QA 백로그 해소)**: "구독서비스 결제 안내"는 이 화면(유료 결제 화면)의 목적을 그대로 명명해 사용자가 이 문구 아래에서 무엇을 읽어야 하는지 즉시 파악하게 한다. 반면 원문 "무료 플랜시 유의사항"은 지금 보고 있는 화면이 유료 결제 진행 화면이라는 맥락과 모순되는 라벨이다(br01-r03-D18 원 기록도 "원문이 모순적이라 개선처럼 보이나 승인 근거 없음"이라고 관찰함). **결론: 실앱 카피가 UX상 개선에 가깝다 — 원복하지 말고 "목업2 원문 표기 오류를 실앱에서 정정한 것"으로 명시 기록한다.** 향후 동일 판단이 필요한 카피 이슈는 "원본과 다르다"는 사실 확인에서 멈추지 않고 이 문단처럼 사용자 이해도 관점의 UX 판단 한 줄을 남길 것.

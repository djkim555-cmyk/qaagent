# [S-BR01-0601-007] 카드 등록
> route: /purchase-card · 정리: 나래님 · 최종수정 2026-07-27 (KST) · 상태: 작성완료

## 기능 정의
- 결제에 사용할 카드 정보를 등록하는 폼. 원본 목업2(`mockup2/src/views/payment/purchase-card.html`)가 "디자인 미확정(원본 미완)" 빈 스텁이라 별도 정책문서가 없으며, 실앱 이식은 앱 디자인 시스템 기존 클래스(`auth-field`/`input-box`/`checkout__notice`)만 재사용해 최소 기능 폼으로 신규 설계됨(신규 색·컴포넌트 발명 금지 원칙 준수).
- 입력 항목: 카드사(셀렉트, 9개사), 카드 종류(신용/체크 토글), 카드번호 뒤 4자리(숫자 검증), 대표 카드 설정 여부(체크박스).
- 제출 시 `POST /api/billing/cards`(⚠️게이트) 호출. 토스페이먼츠 카드 등록 SDK(authKey/customerKey)는 이 스파이크에서 호출하지 않고, 카드사/타입/뒤4자리만 입력받아 계약 shape을 채우는 스텁 값으로 처리.
- 등록 성공 시 "카드가 등록되었습니다" + "실 카드 인증(토스페이먼츠)은 스테이징 게이트로 비활성화되어 있습니다" 안내를 알림 모달로 노출(무음 성공 위장 금지) 후 `next` 쿼리 경로로 이동(기본값 `/my/account`).

## 표시 조건 · 상태·분기
- 카드번호 뒤 4자리는 정규식 `^\d{4}$` 검증 — 불일치 시 "카드 번호 뒤 4자리(숫자)를 입력해 주세요" 에러.
- 제출 실패 시 API 미연동(`BRAND_API_UNREACHABLE`/`UNKNOWN`) 여부에 따라 `MockBadge`("API 미연동") 노출 여부 분기.
- 쿼리 `next`는 `/`로 시작하는 경로일 때만 유효, 아니면 기본값 `/my/account` 사용.

## 정책 (변경 사항 · 값·수치)
- **원본이 빈 스텁이라 별도 정책문서 없음** — `mockup2/src/views/payment/purchase-card.html`을 직접 확인한 결과 실제 퍼블리싱 콘텐츠가 없고 "디자인 미확정(원본 미완)" 안내 텍스트만 존재함을 확인. 상세 정책은 `[추정]` — 신규 설계 + staging 게이트로 처리된 것으로 서술함(개발 세션 주석 근거).
- **오너 확인(금전/결제)** — 카드 등록은 결제 수단 연동이라 위험 항목. 실 카드 승인 미실행(스테이징 게이트) 상태는 정책상 의도된 것으로 판단되나 별도 정책문서에 명문화된 근거는 없음 — `[미확정]` 결정책임자/기한 미정.

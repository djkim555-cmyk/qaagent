# [S-BR01-0801-002] 즉시 결제
> route: /my/product-pay-now · 정리: 나래님 · 최종수정 2026-07-27 (KST) · 상태: 작성완료

## 기능 정의
- 결제 실패/유예/중지 상태의 청구서를 즉시 재결제하는 화면. "선택된 플랜" 요약 카드(플랜명·배지·사이트명·플랫폼 수수료·청구 기간·결제 마감일·재시도 횟수) + "결제 금액 요약"(청구 금액·VAT·미납 이월 금액·산정된 결제 금액) + 결제 카드 선택 + 약관 동의 + 결제 버튼.
- 쿼리: `siteId`(필수 — `my/sites.vue`의 "즉시 결제하기" 버튼이 전달, 결제실패/유예/중지 상태에서만 노출).
- 실연동은 `invoiceId`가 경로 파라미터인 재시도 EP(`POST /api/payments/:invoiceId/retry` ⚠️게이트) 구조상, 이 화면이 먼저 `GET /api/invoices`에서 해당 사이트의 재시도 가능(failed/grace/open) 청구서를 찾는다.
- 재시도는 pending 결제 레코드만 만드는 staging-gate라 승인 여부는 "결제가 완료되었습니다"로 단정하지 않고 `/purchase-complete`가 `paymentId`로 문구를 분기.

## 표시 조건 · 상태·분기
- 로딩/에러/재시도 대상 없음(empty, "이미 정상 처리되었거나 재시도 대상이 아닌 상태입니다") 3분기.
- 미납 이월 금액이 0보다 클 때만 "미납 이월 금액" 행 노출.
- 결제 버튼 비활성 조건: 카드 미선택 또는 약관 미동의.

## 이식 주의 종합
- '구독서비스 결제 안내' 블록 누락은 `product-upgrade-cycle`과 **2화면 공통**(자동연장은 대상 아님, 정정됨). 플랜 등급 배지 누락은 `product-auto-renew`·`product-upgrade-cycle`과 **3화면 공통** — 두 결함의 공통 범위가 다르니 혼동 주의, 개별 수정보다 일괄 이식 권장.
- 실제 결제 금액(산정된 결제 금액)은 `InvoiceDto`의 서버 계산값을 그대로 표시하므로 클라이언트 재계산 로직이 없어(자동연장·플랜업그레이드와 달리) 견적 배지가 붙지 않음 — 화면별 신뢰도 차이에 유의.
- **처리 순서(2026-07-27 3차 UX 후속검증 추가, 2차 QA "blocker 없는 화면 우선순위 부재" 해소)**: 이 화면은 blocker(상)가 없고 중·하 각 1건뿐이나 착수 순서를 명시한다 — ① **중** `checkout__notice`('구독서비스 결제 안내') 블록 복원(`product-upgrade-cycle`과 동시 처리) → ② **하** 플랜 등급 배지(`badge--outline`) 복원(`product-auto-renew`·`product-upgrade-cycle`과 동시 처리). 결제 전 안내 문구 누락(중)이 배지 누락(하)보다 사용자 신뢰·정보 고지 성격상 우선한다.

> 정책 소스(`sites-home-signup.md`)에 회원가입 인증코드 발송 모달 관련 별도 서술 없음 — `mockup2/src/views/auth/signup-code-sent-modal.html`을 직접 확인해 작성.

## 기능 정의
- 회원가입 폼에서 이메일 인증코드 발송 요청 성공 시 뜨는 확인-단독 알럿. 체크 아이콘 + "이메일로 인증코드가 발송되었습니다" 제목 + 유효시간 안내 desc + "확인" 버튼(닫기).
- 목업2는 정적 페이지 형태(단독 열람 시 "확인" 클릭하면 회원가입 화면으로 복귀, 모달로 주입 시엔 공통 `modal.js`가 닫기 처리)였으나, 스파이크는 별도 라우트 없이 `useModal().alert()` 함수 호출로 대체 구현.

## 표시 조건 · 상태·분기
- 회원가입 화면(`signup.vue`)에서 이메일 인증코드 발송 API 호출 성공 시에만 노출.

## 정책 (변경 사항 · 값·수치)
- 유효시간 안내 문구 변경: 목업2 "3분내" → 실앱 "10분내"로 변경, `expiresIn` API 응답 바인딩 없이 **하드코딩**됨(br01-r03-D12). **[확정]로 정정(2026-07-27 3차 UX 후속검증)** — `docs/validation/05_정책설계서.md` §C-2가 "가입/이메일변경 인증코드: Brand 3분 → 10분으로 상향 통일"을 이미 확정했음(`S-BR01-1201-002` 회원가입 인증코드 메일 문서 참조). 값 자체는 정책 확정이므로 되돌리지 않는다 — 남은 과제는 하드코딩 문구를 `expiresIn` 응답 바인딩으로 교체하는 것뿐(아래 디자인 이슈 참조).
- **UX 판단**: 이메일 인증은 사용자가 화면을 벗어나 메일함(다른 탭·앱)을 확인하고 돌아오는 왕복 행동을 요구한다. 3분은 이 왕복(알림 지연·메일 클라이언트 전환 포함)에 촉박해 시간 내 완료 실패 → 재발송 → 이탈로 이어질 위험이 있었던 반면, 10분은 완료율을 높이는 방향의 개선이다. 비밀번호 재설정 링크(`S-BR01-1201-001`, 1시간→30분으로 하향)와 짝지어 보면 "탈취 시 위험이 낮은 코드 입력형(재사용 불가·타이핑 필요)은 여유 있게, 탈취 시 위험이 큰 링크 클릭형은 짧게"라는 일관된 보안↔UX 트레이드오프로 읽혀 두 값 모두 사용자 경험상 타당하다고 판단한다.

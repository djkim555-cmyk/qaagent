# [S-BR01-0901-002] 결제 이메일 변경
> route: /my/account/billing-email · 정리: 나래님 · 최종수정 2026-07-27 (KST) · 상태: 작성완료

## 기능 정의
- 계정 관리 화면의 결제 이메일 입력칸은 표시 전용(disabled, 로그인 이메일을 읽기전용 참고 표시)이며, 변경은 '이메일 변경' 버튼 → 이 화면(`/my/account/billing-email`)에서 새 이메일 입력 → 인증코드 발송/확인 → 비밀번호 확인 → 제출 흐름으로만 이뤄진다.
- 인증코드 발송/확인은 brand-api 범용 EP(`/api/auth/email-code/issue|verify`, purpose=`email_change`)로 실 연동(signup.vue와 동일 6칸 패턴).
- **저장(`billing_email`) 자체는 brand-api에 EP가 없다**(`grep -rn "billing_email|billingEmail" src/routes/*.ts` → 0건) — 인증코드 확인까지 통과해도 실제로 저장하지 않고 "결제 이메일 변경 기능은 아직 지원되지 않습니다." alert로 종료(무음 성공 위장 금지 원칙 준수).

## 표시 조건 · 상태·분기
- 계정 정보 로딩 중/에러 상태(`ApiStateNotice`)로 분기.
- 이메일 형식 미충족 시 "이메일 주소를 입력해 주세요" 에러.
- 인증코드 미완료 시 "이메일 인증을 완료해 주세요" 에러.
- 비밀번호 미입력 시 "비밀번호가 맞지 않네요. 다시 입력해 주세요." 에러 — **실제 서버 대조는 하지 않음(필수 입력 검증만)**.

## 정책 (변경 사항 · 값·수치)
- 인라인 수정 불가 + 모달/별도 화면 변경 방식 유지(계정관리 정책 원칙, `docs/policy/brand/front/account.md`).
- **상태 = mock(계약보류)** — 저장 API(`billing_email`) 자체가 brand-api에 없음. 저장 EP 신설 전까지는 저장 액션이 항상 안내 alert로 종료된다.
- 유효시간 문구 "10분내"(하드코딩, `expiresIn` 미바인딩) — 회원가입 인증코드 모달과 동일 이슈(br01-r03-D12). **[확정]**(2026-07-27 3차 UX 후속검증) — `05_정책설계서.md` §C-2 확정값(`S-BR01-1201-002` 참조), 되돌릴 필요 없음. **UX 판단**: 10분은 사용자가 메일 확인·복귀에 걸리는 현실적 시간을 확보해 완료율을 높이는 개선(근거 상세 = `S-BR01-0301-002_pu01` §정책).

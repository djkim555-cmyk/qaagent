# [S-BR01-0801-003_pu01] 구독 취소 완료 안내(LPU)
> route: /my/product-cancel (모달, 부모=S-BR01-0801-003 구독취소) · 정리: 새롬님 · 최종수정 2026-07-27 (KST) · 상태: 작성완료

## 기능 정의
- mockup2 파일명은 `product-cancel-confirm-modal.html`("구독 취소 컨펌")이지만, **실제 콘텐츠는 Y/N 확인창이 아니라 완료 알림**이다: 아이콘 + "구독 취소가 완료되었습니다" + "내 사이트 관리하기에서 확인하실 수 있습니다" + 확인 버튼 1개.
- mockup2 원본(목업 한정 로직)은 확인 클릭 시 ① `localStorage`에 취소 플래그 저장 ② 구독취소 안내메일을 새 창으로 오픈(`subscription-cancel-email.html`) ③ `/my/sites.html`로 이동, 세 동작을 한 번에 수행한다.
- 스파이크(`app/pages/my/product-cancel.vue:70-75`)는 `DELETE /api/subscriptions/:id`(mode=expire) 성공 후 `useModal().alert('구독 취소가 완료되었습니다', { desc: '내 사이트 관리하기에서 확인하실 수 있습니다', icon: ... })`로 동일 카피를 재현한다(이동·메일 오픈은 스파이크 범위에서 생략).

## 표시 조건 · 상태·분기
- `DELETE /api/subscriptions/:id` 성공 시에만 노출. 실패 시에는 별도 에러 alert(`구독 취소 처리 중 오류가 발생했습니다.`).
- 확인 버튼 외 다른 상태 분기 없음(단순 완료 알림).

## 정책 (변경 사항 · 값·수치)
- 별도 전용 정책문서 없음 — `03_brand-site.md` L704~705 SoT 카피를 그대로 이식한 문구("✕ 빨강 + 구독 취소가 완료되었습니다 + 내 사이트 관리하기에서 확인하실 수 있습니다 + [확인]").
- **[주석]** `S-BR01-0801-001_pu01`이라는 ID가 이 화면과 동일 콘텐츠를 가리키는 것처럼 인용되는 경우가 있으나, 이는 원 SoT(`docs/validation/03_brand-site.md:704`)의 **구 넘버링**에서 유래한 것이다 — 당시엔 0801-001이 "구독취소" 화면이었으나 화면ID 재수확(D03) 이후 0801-001은 "자동연장하기"(`S-BR01-0801-001-자동연장하기.md`)로 재배정되어, 현재 storyboard 체계엔 `S-BR01-0801-001_pu01`에 대응하는 파일이 없다. 이 완료 안내 콘텐츠와 `S-BR01-0801-001_pu01` 구 참조 간 관계(통합할지, 신규/레거시로 역할 분리할지)는 **오너 확인 대기 중**(매핑표 `docs/validation_modified/BR01_화면ID_매핑표.md` §6.4). **2026-07-27 2차 QA 정책·기획 페르소나 권고**: 역할을 나눌 대상(대응 파일)이 없으므로 **통합** — 이 문서(`S-BR01-0801-003_pu01`)를 유일 정본으로 확정 권고(최종 확정은 오너/기획-lead 서명 필요, 근거 = `docs/dev-validation/spike/_storyboard-qa2-policy.md`).
- **오너 확인(비가역·금전 인접)**: 구독취소 실 API 호출은 이미 활성화됨(2026-07-16 오너 승인, accepted-risk). 이 문서 범위에서 재론하지 않는다.

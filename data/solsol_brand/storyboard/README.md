# docs/storyboard — 목업2 화면 스토리보드 (작성 안내)

> **목적** — 화면 하나(화면ID)당 **기능 정의·정책·디자인 이슈를 한 파일에 통합**해 기록한다. 기존에는 [`../policy/`](../policy/README.md)(기능·정책)와 [`../design/`](../design/README.md)(디자인 이슈)로 나뉘어 있어 화면 하나를 보려면 두 파일을 오가야 했다 — 이 폴더가 그 문제를 해소하는 **후속 정본**이다(2026-07-27 오너 결정).
> **적용 순서**: 관리자단(`solsol-admin/`)부터 전량 마이그레이션. 사용자단(`solsol/`)·브랜드(`solsol-brand*`)는 각 세션이 같은 관례로 후속 이관.

## 1. 파일 단위·네이밍

**기록 단위 = 화면(route) 1개당 파일 1개.** 같은 화면ID가 라우트 여러 개에 걸치는 경우(예: 로그인 로고형/텍스트형이 둘 다 같은 화면ID) 화면명으로 자연히 구분되는 별도 파일로 만든다.

```
<제품>/<화면ID>-<화면명 슬러그>.md
예) solsol-admin/S-AD01-0301-001-로그인-로고형.md
    solsol-admin/S-AD01-0301-001-로그인-텍스트형.md
```

- 화면명 슬러그: 화면 앵커 제목(예: "로그인(로고형)")에서 괄호·기호를 제거하고 공백을 `-`로 치환.
- 파일명만으로 화면ID·화면을 바로 식별할 수 있게 하는 것이 목적 — 파일을 열지 않고도 목록에서 검색 가능해야 한다.

## 2. 파일 템플릿 (기능+정책+디자인 통합)

```markdown
# [<화면ID>] <화면명>
> route: <path> · 정리: <이름>님 · 최종수정 YYYY-MM-DD (KST) · 상태: 작성중/작성완료

## 기능 정의
- 이 화면·구성요소가 하는 일(버튼 동작·목록 규칙·폼 검증·계산·상태)을 단정적으로 서술.

## 표시 조건 · 상태·분기
- 상황별 노출/숨김/상태(로그인·권한·상태값·빈 상태·에러·기간), 상태 전이·조건 분기·경계값·실패.

## 정책 (변경 사항 · 값·수치)
- 검수로 결정/변경된 규칙·수치·문구·플로우: 기존 → 변경 (이유). 신규면 "신규".
- 임계값·TTL·길이 등 값·수치. 근거 없는 단정 금지 — `[추정]`/`[미확정]`은 명시하고 `[미확정]`은 결정책임자·기한 병기.
- 비가역·금전(결제·환불·정산·크레딧·탈퇴·약관·외부공개)은 **오너 확인** 표시.
- 확정 상위 정본([`../validation/05_정책설계서.md`](../validation/05_정책설계서.md)·화면설계 `00~03`)과 충돌 시 임의로 정하지 말고 **⚠️충돌 표시 + 오너/기획-lead 확인**.
```

## 3. 표기 규칙 · 상태·이력

- 문장 단위 확정 / `[추정]` / `[미확정]` — `docs/policy/README.md` §3와 동일.
- 각 문서 상단 상태 `작성중 / 검수완료`, 절대 날짜(KST), 정리자 이름+"님".

## 4. `/screens` 연결

- 화면ID → 문서 매핑 정본 = `app/utils/screenDocs.ts`. 각 화면ID는 이제 **하나의 storyboard 문서**를 가리킨다(예전처럼 design/policy 두 갈래 참조가 아님 — 다만 인터페이스 호환을 위해 `design`·`policy` 두 필드 모두 같은 storyboard 문서를 가리키도록 채운다).
- content-path 규칙은 `docs/policy/README.md`와 동일: `docs/storyboard/solsol-admin/S-AD01-...md` → `/storyboard/solsol-admin/S-AD01-...`.

## 5. 기존 `policy/`·`design/`와의 관계

- **관리자단(`creator-admin`)은 이 폴더로 완전히 대체됐다** — `docs/policy/creator-admin/`·`docs/design/creator-admin/`는 삭제됨(2026-07-27). 재론 시 이 문서와 [[admin-mockup2-handoff-rebuild]] 참조.
- 사용자단(`creator/`)·브랜드(`brand/`)는 아직 기존 `policy/`·`design/` 방식을 유지 중 — 해당 세션이 같은 관례로 이관하기 전까지는 기존 문서가 정본이다.
- 신규 화면·신규 검수 산출물은 이관 완료된 제품에 한해 **바로 storyboard 형식으로** 작성한다.

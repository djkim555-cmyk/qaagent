## 2. "코드엔 있는데 문서가 언급 안 한 것" vs "코드에도 없는 것" 요약

### (A) 코드엔 이미 구현돼 있으나 storyboard가 언급 안 한 것 — "관찰 누락"(문서 보강만 필요, 코드 수정 불요)
- 모달 공통: `role="dialog"` · `aria-modal="true"` · `aria-label` · 열릴 때 초기 포커스 · ESC 닫기 (11개 모달 문서 전체)
- 비밀번호 표시/숨기기 토글의 `role="button"`+키보드 핸들러(로그인·새비밀번호설정)
- 토글 스위치의 `aria-pressed`(계정관리 마케팅수신/2단계인증)
- 인증코드 6칸 입력의 개별 `aria-label`
- 케밥 메뉴 트리거가 실제 `<button>`이라 Enter/Space로 열림(문의내역상세)
- 에러화면 4종의 장식 이미지 `alt=""`/로고 `alt="쏠쏠"`/`<h1>` 단일 구조
- 이메일 12종 전건의 `alt` 텍스트·`<h1>`·`lang="ko"` (QA2가 "이메일 체크 항목이 아예 없다"고 지적한 그 자리 — 실제로는 코드가 이미 상당히 양호했다)

이 그룹은 **개발 결함이 아니다** — storyboard가 실제 구현 수준을 과소평가하고 있을 뿐이므로, 문서에 1줄 각주만 추가하면 해소된다.

### (B) 코드에도 구현이 없는 것 — 실제 결함(문서·코드 양쪽 다 손볼 대상)
- **포커스 트랩 부재**(모달 11종 공통, 중) — Tab이 모달 밖으로 샌다
- **닫힌 후 포커스 복귀 부재**(모달 11종 공통, 중)
- **배경 스크롤 잠금 부재**(모달 11종 공통, 하~중)
- **필드별 에러의 `aria-describedby`/개별 `role="alert"` 부재**(회원가입·로그인·새비밀번호설정·계정관리·카드등록·문의하기 6개 폼 전체, 중) — 전 폼 공통 패턴이라 공용 컴포넌트화 시 한 번에 해소 가능
- **결제내역 상태 필터가 키보드로 절대 열리지 않음**(상, blocker급) — `readonly input` 트리거 + click 전용 델리게이션의 구조적 한계
- 케밥 메뉴의 `aria-expanded` 부재(문의내역상세, 중) + ESC 닫기 부재(하~중)
- "더보기" 버튼 Space 키 미지원(문의내역목록, 하)
- purchase-card.vue만 `formError`에 `role="alert"` 누락(앱 내부 비일관, 하)
- 회원가입/비번재설정 인증메일 2종의 안내문·수신거부 링크 색상 대비 확정 미달(중) + 10종 CTA 버튼 대비 경계선 미달(하)

## 3. D16(케밥 기본액션 부재)과의 관계

D16(화면QA 결함 — 케밥 메뉴에 클릭해도 반응하는 기본 액션이 없다는 취지로 추정)과 이번 회차에서 발견한 접근성 결함은 **레이어가 다르다**:
- D16류는 "케밥을 열었을 때 항목이 계약 미비(EP 없음)라 MOCK 안내만 뜬다" — **기능/계약 문제**.
- 이번 회차는 "케밥은 열리지만(마우스·키보드 둘 다 가능) **열림 상태를 스크린리더가 못 알아챈다**(`aria-expanded` 부재)" · "**ESC로 못 닫는다**" — **인터랙션 시맨틱 문제**.
- 결제내역 상태 필터는 한 단계 더 심각 — **키보드로는 아예 열리지도 않는다**(마우스 필수). D16과 달리 이건 "메뉴 안 내용"이 아니라 "메뉴를 여는 행위 자체"가 막혀 있다.

두 관점 모두 같은 화면(결제내역·문의내역상세)을 가리키지만 서로 다른 결함이므로, 케밥/셀렉트를 공용 컴포넌트로 리팩터링할 때 **기능 결함(D16) 수정과 접근성 결함(포커스/ARIA/키보드) 수정을 같은 작업에서 함께 처리**하는 것이 효율적이라는 점만 메모해 둔다(작업 배정은 QA 소관 밖).

## 4. 확인 불가 항목(코드로 판단 못 함)

- 에러 화면 4종의 CSS 변수(`--text-*`) 실제 렌더 색상 — `docs/design/brand/tokens.md`와 실제 브라우저 렌더 대조 필요(본 세션은 인라인 hex 값이 있는 이메일만 정량 계산했고, CSS 변수 참조 화면은 판정 보류).
- 실제 스크린리더(VoiceOver/NVDA) 실기 테스트 — 본 검토는 정적 코드 대조까지만 수행, 실기 낭독 검증은 별도 라운드 필요.

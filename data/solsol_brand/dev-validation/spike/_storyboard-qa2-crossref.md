## 2. pu01/pu02 상호참조 검토(신규, `S-BR01-0401-001_pu01`↔`_pu02`)

**결과: 문제 없음.**

- 양쪽 파일 모두 헤더에 `[2026-07-27 분리]`/`[2026-07-27 신규 분리]` 각주로 분리 배경(매핑표 §3.1)을 동일하게 서술하고, 상대 파일을 마크다운 링크로 정확히 상호 참조(`pu01`→`pu02` 3곳, `pu02`→`pu01` 4곳, 전부 파일 존재 확인).
- **내용 정합성**: "MOCK(계약보류)"였던 브리프 표기가 실측 결과 실 API(`GET /api/sites/check-slug`) 연동으로 확인됐다는 정정 서술이 **두 파일에 토씨 하나까지 동일하게** 반영됨(공통 서술은 의도적으로 양쪽에 중복 기재한다고 헤더에 명시돼 있고 실제로 그렇게 되어 있음) — 한쪽만 고쳐지고 다른 쪽이 구버전으로 남는 현상 없음.
- 도메인 표기(`.solsol.com`→`.solsol.live`) stale 관찰도 양쪽에 병렬 기재, "사용 가능"/"사용 중" 상태별 고유 내용(아이콘·문구)만 서로 다르게 정확히 분리됨.
- mockup2 실파일 존재·내용 재확인: `sites-create-domain-available-modal.html`·`sites-create-domain-taken-modal.html` 둘 다 존재, `sites-create-domain-taken-modal.html:28`의 `example-site.solsol.com` 구표기도 pu02 문서의 인용과 정확히 일치.
- **결론**: pu01/pu02 분리로 인한 신규 교차참조 문제 없음. 오히려 "두 상태 파일 모두 독립적으로 읽혀야 한다"는 원칙을 명확히 지켜 중복 기재 자체가 의도된 설계.

## 3. 신규 발견

### 3-1. 커밋 `71f948d` 날짜 인용 오류 (신규, 하)

- `S-BR01-0401-001_pu01-도메인-중복확인-모달.md:19`·`S-BR01-0401-001_pu02-도메인-사용중-안내.md:19` 두 파일 모두 "도메인 표기 변경: 목업2 `.solsol.com` → 실앱 `.solsol.live`**(2026-07-16**, 커밋 `71f948d`)"로 서술.
- **실측**: `git log -1 --format='%H %ad' 71f948d` → `2026-07-20 16:58:30 +0900`. 즉 실제 커밋 날짜는 **2026-07-20**이며 **2026-07-16이 아니다**(4일 차이).
- 추정 원인: 같은 화면·인접 영역에서 2026-07-16에 몰려 있던 다른 변경(라우팅 충돌 수정·홈 CTA·검수로그인 등, `docs/design/brand/_changelog.md` 8~14행 다수)과 날짜를 혼동한 것으로 보임 — `_changelog.md`에는 이 도메인 접미사 변경 자체의 항목이 없어(grep 결과 0건) 별도 출처 확인 없이 인접 날짜를 재사용한 것으로 추정.
- **영향**: 커밋 해시 자체(`71f948d`)는 정확하고, 이 커밋이 도메인 접미사 변경을 다룬다는 사실관계도 맞음 — **날짜 숫자만 오기**. 기능·정책 판단에는 영향 없으나, 향후 "언제 배포됐는지" 타임라인 재구성 시 4일 오차를 유발할 수 있음.
- **심각도**: 하. **후속 조치**: 두 파일의 "2026-07-16" → "2026-07-20"으로 정정 권고(나래/새롬 담당).

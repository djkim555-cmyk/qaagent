## 3. 신규 검토 3개 관점

### 3-1. 인증코드/토큰 만료 정책 보안 영향 — 안전
- 확정값 코드 일치: `EMAIL_CODE_TTL_SEC=600`(10분)·`RESET_TICKET_TTL_SEC=1800`(30분) — storyboard 서술과 정확 일치.
- 6자리 코드 brute-force 저항: 서버 `max_attempts=5` 강제(초과 시 `locked`), 재발급 시 직전 코드 `superseded` 무효화.
- 토큰은 전부 `crypto.getRandomValues` 사용, reset 토큰 256비트 불투명값, code_hash 서버 저장·응답 미노출.

### 3-2. 구독취소 API 서술 변경의 코드 영향 — 없음(정상)
- "0801-001_pu01 통합" 서술은 화면ID 정리일 뿐, `DELETE /api/subscriptions/:id`의 소유권 검증·멱등성(취소완료 재요청 400 거부)에 영향 없음.

### 3-3. 1201 이메일 12종 발신 트리거 보안 — 현시점 위험 없음
- 결제유예/중지/중단 등은 서버 이벤트(cron/webhook) 기반, 클라이언트 트리거 API 없음.
- 클라 호출 가능한 발신 유발 EP 2개(`/email-code/issue`·`/password/reset-request`) 모두 현재 실발송 미구현(TODO) — 폭탄 발송 경로 부재.
- 참고(하드닝 권고, blocker 아님): 실메일 연동 착수 시 `/email-code/issue`에 rate limit 추가 권고.

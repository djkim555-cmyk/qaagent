## 2. 모달·케밥 키보드 접근성 관점 부재 — 부분 해소(모달 5종 실행 완료, 실제 코드 대조로 정확도 확보)

**수정 완료 파일**(5개, `S-BR01-0901-001_pu01`~`pu05` 전량):

## 3. D09 비대칭 서술 — 해소(3개 문서 동일 캐노니컬 목록으로 통일 + 실제 코드 근거로 목록 확장·정정)

**재평가**: 2차 QA는 "새비밀번호설정 문서만 로그인·회원가입을 이름으로 열거하고 나머지 2개는 뭉뚱그린다"고 지적했다. 실제로 `docs/storyboard/solsol-brand`에서 D09를 언급하는 문서는 `S-BR01-0302-003`(새 비밀번호 설정)·`S-BR01-0701-001`(문의하기)·`S-BR01-0601-007`(카드등록) 3개뿐이었고, 서로 다른 문구("인증 폼 전반(로그인·회원가입·문의하기 등)" vs "인증 폼 전반의 반복 이슈")로 뭉뚱그려 정확한 전체 목록이 어디에도 없었다 — 지적 유효.

**실행**: `grep -rln input-box--error app/pages`(브랜드 사용자단 실 코드)로 실제 영향 범위를 재확인한 결과 9개 화면이 해당 클래스를 쓰는데 에러아이콘(`input-box__erricon`)을 실제로 갖춘 화면은 `password-reset.vue`(비밀번호 찾기 요청) **1건뿐**이었다 — 즉 2차 QA가 추정한 "3개 화면" 문제가 아니라 실제로는 **8개 화면**(로그인·회원가입·새비밀번호설정·문의하기·카드등록·결제이메일변경·계정관리·사이트생성)에 걸친 문제였다.

**수정 완료 파일**(4개):
- `S-BR01-0302-003-새-비밀번호-설정.md` — 종합 섹션에 8개 화면 캐노니컬 목록 추가
- `S-BR01-0701-001-문의하기.md` — 동일 목록(상호 참조 문구 포함)
- `S-BR01-0601-007-카드등록.md` — 동일 목록(상호 참조 문구 포함)
- `S-BR01-0901-002-결제-이메일-변경.md` — 이 화면도 영향권임을 발견해 참고 링크만 추가(3개 원본 문서와 동일 목록을 인용하도록)

**적용한 문구 핵심 요약**: "`grep -rln input-box--error app/pages` 9건 중 에러아이콘을 갖춘 화면은 `password-reset.vue` 1건뿐 — 나머지 8개 화면(로그인 S-BR01-0302-001·회원가입 S-BR01-0301-001·새비밀번호설정 S-BR01-0302-003·문의하기 S-BR01-0701-001·카드등록 S-BR01-0601-007·결제이메일변경 S-BR01-0901-002·계정관리 my/account.vue(storyboard 미작성)·사이트생성 my/sites/create.vue(storyboard 미작성))이 영향권. 공통 컴포넌트화 시 이 8개 전체 대상." 3개 문서가 문자 그대로 동일한 목록을 인용하도록 통일(더 이상 비대칭 없음).

**남은 갭(미검증)**: 계정관리(`my/account.vue`)·사이트 생성(`my/sites/create.vue`)은 아직 화면ID/전용 storyboard 문서가 없어(각각 `S-BR01-0901-001` 상위 문서 미작성, 사이트 생성 미배정) 목록에는 코드 경로로만 넣었다 — 이 두 화면의 정식 storyboard화는 이번 작업 범위 밖.

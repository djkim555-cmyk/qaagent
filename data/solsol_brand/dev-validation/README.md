# docs/dev-validation — 검증 운영 헌장 (README)

> **이 폴더의 단일 진입점.** "검증을 어떻게 **운영·진행·기록·보고**하는가"의 실무 규칙을 정의한다.
> **축·프로파일·심각도·게이트의 *정의*는 [../DEV_VALIDATION_PROCESS.md](../DEV_VALIDATION_PROCESS.md)(정본)** 를 따르고 여기서 재정의하지 않는다. 이 문서는 그 정본을 **폴더 운영 규칙으로 구체화**한다.
> 제정: 2026-07-09 (KST) · 담당 논의(도담·미쁨·가림·바다·매듭) 종합 · 총괄(가온).

## 0. 이 폴더의 역할·경계 (무엇을 두고 무엇을 안 두나)

- **둔다**: ① **유형별 하위폴더**(디자인·퍼블리싱·목업·스키마·스파이크·구현)에 결함표 `<유형>/<영역>-r<NN>.md` · ② blocker 이월 원장 `_ledger.md`(단일·교차) · ③ 커버리지 `_coverage.md`(단일) · ④ 이 헌장 `README.md`.
- **안 둔다**: 위원회 **종합·판정·오너보고**는 [`../report/`](../report/README.md)(결함 1건 단위는 여기, 종합은 거기 — 층 분리). 검증 **정본(SoT)** 은 [`../validation/`](../validation/)(읽기전용 불변).
- **소유·경합(§9 정합)**: 결함표는 **각 세션이 자기 파일만** 쓴다. `_ledger`·`_coverage`·`README`는 **허브 단독 쓰기**. 제품 세션은 결과를 자기 결함표에 남기고 **허브에 한 줄 신호**(결함ID·상태·근거·커밋) → 허브가 배치 전사([../DEV_SESSION_PROTOCOL.md](../DEV_SESSION_PROTOCOL.md) §9).

## 1. 파일 분류·네이밍 — 유형(6종) × 영역

**검증 대상 = 구현 과정의 6가지 유형**(오너 확정 2026-07-09). 구현 과정에서 나온 모든 산출물이 검증 대상이며, **유형마다 별도 하위폴더에 보관**한다(각 유형은 **복수 라운드 병행** 가능). 각 폴더 안에서 `<영역>-r<NN>.md`로 라운드를 쌓는다.

```
docs/dev-validation/
  README.md · _ledger.md · _coverage.md          (헌장·원장·커버리지 = 단일·허브 단독)
  design/          디자인 검증
  publishing/      퍼블리싱 검증
  mockup/          목업 사이트 검증
  schema/          DB 스키마 검증
  spike/           스파이크 사이트 검증
  implementation/  구현 사이트 검증
     └ <영역>-r<NN>.md      예) design/fr01-r01.md · mockup/br01-r02.md · schema/data-r01.md · implementation/ad01-r03.md
```

| 유형 폴더 | 검증 대상(산출물) | 프로파일(정본 §2) | 주 검증축 |
|---|---|---|---|
| `design/` | 디자인 시안·토큰·핸드오프 | 디자인 검수(경량) | 토큰·컴포넌트·시각·접근성 |
| `publishing/` | 퍼블리싱 산출물(정적 마크업·1px 재현) | 목업/퍼블 | 9축 중 존재·IA·카피·토큰·반응형 |
| `mockup/` | 목업 사이트(기능 흐름·mock 데이터) | 목업 | 화면 9축(가짜 데이터 전제) |
| `schema/` | DB 스키마·마이그·ERD·시드 | 데이터/계약 | 데이터 5축(§6-데이터) |
| `spike/` | 스파이크 사이트(PoC·1차 개발) | PoC(경량·가설) | 리스크 축소·가설 판정 |
| `implementation/` | 구현 사이트(실앱·실연동) | 구현/실연동 | 9축 전체 + 실연동 + 데이터 5축 + security·privacy 서명 |

- **영역 = 검증 대상 범위(6종, 오너 확정 2026-07-09)**: `fr01`(쏠쏠 사용자단) · `ad01`(쏠쏠 관리자단) · `api`(쏠쏠 백엔드) · `br01`(브랜드 사용자단) · `ba01`(브랜드 관리자단) · `brandapi`(브랜드 백엔드). 파일명 = `<영역>-r<NN>.md`(유형 폴더 안). **스키마 검증**은 `schema/` 유형에서 해당 백엔드 영역으로 기록(`schema/api-*`=쏠쏠 tenant `solsol_lms` · `schema/brandapi-*`=브랜드 master `solsol`, ERD 통합은 허브).
- **`r<NN>` = (유형 × 영역)별 전역 단조증가**. **복수 라운드는 번호를 이어간다**(리셋 금지). committee/reverify/carveout 등 성격·phase·위원회 회차는 **파일명이 아니라 헤더 메타**(§3-헤더)로.
- 유형·영역 신설은 **헌장 개정으로만**. 과거 난립(`-round1`·`phase1a`·`committee-*`·`wiring-*` 계열 혼재)은 이 유형×영역 단일 규칙으로 대체한다.
- **위원회 합동 라운드**도 결함이 귀속된 **유형×영역** 파일에 기록(합동 종합은 `../report/`).

## 2. 라운드 진행 (착수 트리거 + 6단계 lifecycle)

### 2-1. 착수 트리거 (4종 중 하나면 개시 — 없이 열지 않는다)
- **T1 준비완료 신호**: 제품 세션이 배포 + 샘플 Aurora 적용 + `MOCK` 배지 0 선결 후 허브에 신호.
- **T2 재검증 트리거**: `*.sql`·`ERD.md`·`schema*.ts` 변경(§6-데이터) → 데이터 라운드 N+1 **필수**.
- **T3 시정 재검**: 직전 라운드 open blocker 시정 회신.
- **T4 지정**: 오너/팀장 지정 전수·주기 위원회.

### 2-2. lifecycle (6단계 상태머신)
```
① 착수전  추적키 확정(화면ID/EP/테이블) + 참조경로 + 프로파일 선택(정본 §2)
② 구현·셀프 담당개발 축 자가점검 + typecheck/build 증거(§3-증거)
③ 게이트  허브가 렌즈 독립 스폰 → 축별 ⭕/🔺/❌ + 표준 결함표
④ 판정·컨펌 매듭 통합 → blocker 0 검산 → 판정 4종(§5)
⑤ 배포   GO/조건부GO(조건충족) 시만 · 실앱·실연동 blocker 0 강제(우회 불가)
⑥ 기록   _ledger·_coverage 배치 갱신 + history 요약 + report rollup
```
- **게이트 독립 실행 = 허브 단독**. 개발한 세션이 자기 걸 검증하지 않는다(자기참조 금지). 라운드 헤더에 `검증주체=허브 / 개발주체=<세션>` 명기. **서명자 = 개발 담당이면 서명 무효**(역할 분리).
- **결함 상태 전이**(원장 어휘 통일): `open` → `closed@r<NN>`(해소·렌즈서명 필수) / `이관`(후속 라운드·다른 ID 승계, 사유·승계처 필수) / `강등`(상→중/하, 승인자·사유) / `won't-fix`(오너수용, 승인자·사유). 원 라운드 내 해소 가능은 반드시 `closed`, 스코프 밖만 `이관`.

## 3. 결함표 표준 (기록물 ①)

**표준 1종만** 사용(요약형 `심각도|결함|조치` 금지). 정본 [DEV_VALIDATION_PROCESS.md §6](../DEV_VALIDATION_PROCESS.md) 템플릿:

```
| 결함ID | 추적키(화면ID/EP) | 검증축 | 심각도(상/중/하) | 현상(재현절차) | 기대 vs 실제 | 근거(파일:라인/SoT) | 제안 | 담당 | 상태(open/이관/closed@r) |
```

- **결함ID = `<영역>-r<NN>-D##`**(안정 ID). **축코드 접두 금지**(`SEC-`·`DAT-`·`PRV-` ✗ — 축은 "검증축" 컬럼에 이미 있음). 영역은 §1 7종.
- **현상(재현절차) 필수 3요소**: ① 계정/역할 ② 경로/URL ③ 관찰값. 누락 시 **접수 반려**.
- **심각도 상/중/하 단일**(`blocker`='상' 동의어). 판정기호 ⭕🔺❌는 축 단위(결함등급과 별개).

### 헤더 메타(파일 첫 5줄 고정 순서)
```
> 상태: 작성중/완료 · 최종수정 YYYY-MM-DD(KST) · 라운드 성격: <구현/committee/reverify/carveout>
> 프로파일(정본 §2): <목업/구현/계약/실연동> · 대상: <영역·화면ID/EP 목록>
> 검증주체=허브 / 개발주체=<세션> · 게이트 렌즈: <qa/security/privacy/dba>
```

### 정적검증 증거 블록 (모든 라운드 필수)
```
| 레포 | 명령어 | EXIT | baseline 오류수 | 신규 오류수 |
```
- build(EXIT 0/1)와 typecheck(신규 오류수) **분리 표기**. baseline은 **최초 기록 라운드를 인용**(재측정 금지, 출처 라운드 명시). **미실행 시 EXIT 칸에 문자열 `미실행`+사유** — 공란·성공 포장 금지.
- 접수 게이트 3강제: **① 증거블록 有 ② 재현 3요소 有 ③ 결함ID 형식 준수** — 미충족 반려.

## 4. blocker 이월 원장 `_ledger.md` (기록물 ②)

모든 **상(blocker)** 을 등재해 "blocker 0"을 검산하는 단일 원장. **허브 단독·배치 기록**(라운드/배포 종료 시 1회). 컬럼을 정규화해 기계 검산이 되게 한다.

```
| 결함ID | 등재시각(KST) | 발견라운드 | 추적키(+소유트랙) | 심각도 | 요약 | 상태 | 처분유형 | closed라운드 | 서명(역할:판정·근거) | 승인자·사유 |
```

- **처분유형(enum 5종)**: `closed` / `이관` / `강등` / `won't-fix` / `미통과배포`. `closed`·`강등`을 한 칸에 뭉개지 않는다.
- **검산 규칙**: 검산 대상 = `상태=open AND 심각도=상`. `won't-fix`·`이관`은 제외하되 **제외 근거를 검산 주석에 매번 명시**. 검산 포맷:
  `@<라운드>(<날짜>): open=<N> [결함ID…] → 종료조건 <충족/미충족>(<GO/NO-GO>)`. **소유트랙(쏠쏠/브랜드) 태그**로 트랙 혼동 방지.
- **재발**: closed된 ID가 후속 라운드 재발 시 **신규 ID로 등재 + 요약에 `(구 <ID> 재발)`**.
- **승인 필수**: `강등`·`won't-fix`·`미통과배포` 행은 `승인자·사유` 공란이면 **자동 무효**.
- **데이터 원인 태그**(§6-데이터): 요약 앞에 `[DDL위반]`/`[ERD드리프트]`/`[06참고오류]`.

## 5. 판정·서명 (게이트 결과)

- **종합 판정 4종만**(영문 병기 금지): **GO**(open blocker 0 + 렌즈서명 완비) / **조건부 GO**(blocker 0이나 운영 전 조건·이관 잔존, 조건 명시 의무) / **HOLD**(blocker 유보, 해당 기능만 노출 보류) / **NO-GO**(open blocker ≥1, 실앱 우회 불가). 정의 정본 = [DEV_VALIDATION_PROCESS.md §4](../DEV_VALIDATION_PROCESS.md).
- **렌즈 서명 3-state**: `GRANTED` / `조건부(조건 명시)` / `NO-GO`. **형식**: `security(미쁨): GRANTED — 근거 <파일:라인>`. **파일:라인 없는 서명 무효.**
- **실연동 = AND 게이트**: `GO ⇔ security∈{GRANTED,조건부} AND privacy∈{GRANTED,조건부} AND qa∈{GO,조건부} AND (데이터변경 시) dba서명 AND open blocker=0`. **하나라도 NO-GO면 라운드 NO-GO. qa 단독 GO 산출 불가.**
- **조건부 GO의 선결조건**은 원장 `승인자·사유`에 텍스트로 등재(모호한 "추후 조치" 금지). 조건 미충족 배포는 `미통과배포` 처분으로만.

## 6. 증거 표준 (렌즈별) + 커버리지

렌즈별 최소 증거를 결함표 `근거` 칸/증거블록에 남긴다. **값 자체 금지, 위치·유형·패턴·건수만**(§8).

- **화면 9축(qa)** — 정본 §3-A. 커버리지는 `_coverage.md`(아래)로 검산.
- **보안 4종(security)** — 정본 §3-C. ① 인증/세션: 보호라우트 `N/N`·무토큰 401·JWT flags 위치 ② RBAC/IDOR/own: owner 판정 `code-파생` 조인경로·self-grant 차단 파일:라인·타테넌트 403 ③ 시크릿: grep 대상(dist/로그/응답/커밋)·패턴·`hit=0`·명령+EXIT ④ 레이트리밋/계정열거.
- **마스킹 3레이어(privacy)** — 정본 §3-D. L1 응답(본인 vs 타인 분기·필드명·마스킹여부) / L2 로그·에러(평문 금지 필드·출처·건수) / L3 외부전송(전송처·필드유형·국외이전·동의근거). **국외이전 동의 미비 = 상**(법무 에스컬레이션, 단독 GO 금지). **비가역(삭제·환불·파기)** 확인 UX 없으면 상.
- **데이터 5축(dba)** — 정본 §3-B. 축별 필수 증거(①스키마 4자 `sql↔ORM↔ERD↔계약` 병기 ②마이그 멱등·롤백·파괴적 ③시드 멱등 ④정합성 UNIQUE·멱등키 재현쿼리 ⑤성능 EXPLAIN). **증거 공란 축 = 자동 `❌`(미검증)**.
  - **재검증 트리거·스냅샷**: `*.sql`·`ERD.md`·`schema*.ts` 변경 diff 있으면 데이터 라운드 N+1 필수(스킵 = 상). 종료 시 스냅샷 고정: `master=<N>테이블(commit) / tenant=<N>(commit) / ERD(commit) / ORM(commit)` + 3자 카운트 IDENTICAL.
  - **데이터 권위**(불변): ① 구현 DDL → ② ERD.md(파생) → ③ 06_API계약(참고, 정본 아님). 06 불일치 자체는 결함 아님.

### 화면ID 커버리지 `_coverage.md` (기록물 ③ — 신설)
SoT(`../validation/00_화면목록.md`, 개정본 우선) ↔ 구현 1:1 매핑을 **위원회 라운드 단위**로 갱신.
```
| 화면ID | 영역 | 구현확인 최종라운드 | 검증제외(사유) | MOCK배지 잔존 |
```
종료조건 3: **누락 0**(SoT에 있으나 무등장) · **검증제외 오존재 0** · **MOCK 배지 0**(실앱 한정).

## 7. 보고 rollup (3층)

## 7-B. 검증 기준 개정 제안 (SoT 피드백 루프) — `validation_modified/`

검증 라운드·보고서가 나온 뒤 **결함이 아니라 "검증 기준(SoT) 자체가 틀렸거나 바뀌어야 한다"** 고 판단되면, 원본을 고치지 않고 **[`../validation_modified/`](../validation_modified/README.md)에 개정 검증 문서를 만들어 제안**한다.

**결함 vs 기준 개정 — 구분(중요)**
- **결함**: 구현이 현행 기준(SoT)을 안 지킴 → 결함표 등재, **개발이 시정**(기준은 그대로).
- **기준 개정**: 기준(SoT) 자체가 실제·정책과 불일치 / `[추정]`·`[미확정]`이 라운드에서 확정 / 정책 충돌·화면 신설·폐기 → **기준을 바꿔야 함**(구현 시정으로 안 닫힘).

**개정 제안 트리거(라운드/보고서에서 발견)**
- SoT(05 정책·00~03 화면·04·PNG)와 실제 확정 정책 불일치 · `[추정]`/`[미확정]`의 라운드 확정 · 정책 충돌(05 확정 6건 상충) · 화면 신설/폐기.
- **검증 축·프로파일·심각도 기준 자체**의 조정은 SoT가 아니라 **절차 정본 [`../DEV_VALIDATION_PROCESS.md`](../DEV_VALIDATION_PROCESS.md) 개정**(허브·오너 승인) + 필요 시 이 헌장 개정.

**절차([`../validation_modified/README.md`](../validation_modified/README.md) 준수)**
1. 라운드 결함표/보고서에 **`[기준개정필요]` 플래그** + 대상 SoT 파일·현행값·제안값·근거(결함ID 연결) 명시.
2. **오너/기획-lead 승인 필수**(정본 개정, [DEV_VALIDATION_PROCESS §0](../DEV_VALIDATION_PROCESS.md)). 승인 없이 개정본 생성 금지.
3. 승인 후 **허브**가 `../validation_modified/<원본과 동일 파일명>`에 **개정 완성본**(부분 diff 아님) + `../validation_modified/_개정이력.md`에 rev·사유·승인자·**전후** 기록.
4. **개정본이 현행 정본** → 이후 라운드·재검증은 **개정본 우선(없으면 원본)** 기준으로 판정. 파생(ERD·screenList 등) 동기화는 소유 세션.
5. 개정 반영 후 관련 결함/기준 이슈는 결함표·원장 상태를 갱신(개정 반영 라운드 명시). **원본 `../validation/`은 읽기전용 불변**.

## 8. 산출물 PII·시크릿 금지 (전 기록물 공통)

- **커밋 전 secret 패턴 grep 1회**(허브) — hit 시 커밋 차단. security·privacy 서명에 "산출물 마스킹 준수 확인" 포함.

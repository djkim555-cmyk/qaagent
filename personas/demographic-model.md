# 페르소나 인구통계 모델

QA 페르소나를 **한국 인구통계학적 분포에 근거**해 생성하기 위한 기준 문서입니다.
`persona-seed.json`의 기본 20인은 이 모델을 따릅니다. 인원 추가·재생성 시에도 이 분포를 유지하세요.

## 1. 왜 분포가 중요한가

20명이 임의로 뽑히면 "젊고 디지털에 능숙한 사용자"에 편향되어, **실제 서비스에서 이탈이 가장 많이 일어나는 고령층·저친숙층·접근성 취약층의 문제를 놓칩니다.**
사람이 하던 사용성 테스트의 핵심 가치는 "다양한 실사용자가 어디서 막히는가"이므로, 분포 충실도가 곧 리포트 신뢰도입니다.

## 2. 기본 분포 (20인 기준)

| 축 | 분포 | 근거/의도 |
|----|------|----------|
| **연령대** | 10대 2 · 20대 4 · 30대 4 · 40대 4 · 50대 3 · 60대+ 3 | 경제활동·온라인 이용 인구 분포 반영, 고령층 의도적 포함 |
| **성별** | 남 10 · 여 10 | 균형 |
| **지역** | 수도권 10 · 비수도권 10 | 수도권 인구집중(약 50%) 반영, 지역 격차 관찰 |
| **디지털 친숙도** | 상 7 · 중 8 · 하 5 | "하" 비중을 의도적으로 확보(고령·저친숙 이탈 관찰) |
| **주 사용기기** | 모바일 12 · PC 5 · 둘다 3 | 국내 모바일 우위 트래픽 반영 |
| **접근성 특성** | 노안·저시력·색약 등 2~3인 포함 | 접근성(A11y) 결함 검출 |

> 위 표는 census 정밀값이 아니라 **QA 커버리지를 위한 의도적(purposive) 층화표본**입니다. 아래 실제 통계로 보정합니다.

### 2-1. 실제 한국 인구 통계 (보정 기준)

| 연령대 | 실제 인구 비중 | 비례배분 시(20명) |
|--------|---------------|------------------|
| 10대 | 9.2% | 2명 |
| 20대 | 13.1% | 3명 |
| 30대 | 13.1% | 3명 |
| 40대 | 15.9% | 3명 |
| 50대 | 16.6% | 4명 |
| 60대 | 13.5% | 2~3명 |
| 70대+ | 11.1% | 2명 |

*출처: 행정안전부 주민등록 인구통계(2025.6, 평균연령 43.4세). 10세 미만(7.5%)은 독립적 서비스 이용자가 아니므로 제외 후 정규화.*
*지역: 수도권 50.8% / 비수도권 49.2% — 통계청 2024 인구주택총조사(수도권 2,631만 명).*

### 2-2. 왜 비례배분을 그대로 쓰지 않는가 (purposive sampling)

UX 사용성 테스트의 표본은 인구 비례가 아니라 **"문제가 가장 많이 발생하는 집단을 확보"**하는 목적표집을 씁니다.
- 비례배분대로면 디지털 친숙도 '하'·고령·접근성 취약층이 과소대표되어 **정작 이탈이 큰 지점을 못 잡습니다.**
- 따라서 기본 20인은 실제 분포(50대+가 큰 비중)를 **반영하되**, 고령·저친숙·접근성 그룹을 의도적으로 충분히 포함합니다.
- 인구 비례에 더 충실한 패널이 필요하면 위 "비례배분" 열을 그대로 적용하세요(50대 4·40대 3·60대+ 4~5로 상향).

> 기본 seed(현재): 10대 2·20대 4·30대 4·40대 4·50대 3·60대+ 3. 실제 통계 대비 20·30대가 다소 많고 50·60대가 적습니다.
> **더 현실적으로 보정하려면** 20대·30대에서 각 1명을 50대·60대+로 이동(→ 10대 2·20대 3·30대 3·40대 4·50대 4·60대+ 4)하는 것을 권장합니다.

## 3. 페르소나 속성 스키마

각 페르소나는 단순 인적사항이 아니라 **행동을 결정하는 심리·기술 속성**을 가져야 진짜 사용자처럼 테스트합니다.

| 필드 | 설명 |
|------|------|
| `id` | P01, P02 … (추가 시 P21~) |
| `ageBand` / `age` | 연령대 / 구체 나이 |
| `gender`, `region`, `city`, `occupation` | 인구통계 기본 |
| `digitalLiteracy` | 상/중/하 — 탐색 속도·오류 회복력 결정 |
| `primaryDevice` | 모바일/PC/둘다 — 테스트 뷰포트 결정 |
| `accessibility` | 노안·저시력·색약 등 — A11y 체크 트리거 |
| `goals` | 이 서비스에서 이루려는 목표(태스크 동기) |
| `personality` | 인내심·의심·탐색성 등 행동 성향 |
| `techBehavior` | 실제 조작 습관(뒤로가기, 확대, 멀티탭 등) |
| `frustrationTriggers` | 이탈/불만을 유발하는 요소 |
| `quote` | 1인칭 대표 발화(리포트 인용용) |

## 4. 인원 확장 가이드 (QA 인원 추가)

1. 추가 인원 수를 정한다(예: +10 → 총 30).
2. 위 분포 비율을 유지하며 새 stratum을 채운다(특히 "하" 친숙도·고령·접근성 비중 유지).
3. `persona-seed.json`의 `personas` 배열에 동일 스키마로 append, `distributionSummary` 갱신.
4. 워크플로우(`persona-qa.js`)는 배열 길이에 맞춰 자동으로 fan-out 한다 — 코드 수정 불필요.

## 5. 특수 목적 페르소나(선택)

서비스 성격에 따라 아래를 추가로 섞을 수 있습니다.
- **악의적/엣지 사용자**: 비정상 입력·중복 제출·뒤로가기 남용 (기능버그 검출 강화)
- **외국인/다국어 사용자**: 한글 미숙, 번역 의존
- **고액 결제자**: 보안·신뢰 신호에 극도로 민감

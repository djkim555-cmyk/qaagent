# 통합테스트 시나리오 — 쏠쏠(CA) 크리에이터 CMS & 프론트 구매 흐름

---

## 1. 서비스 개요
- **서비스명**: 쏠쏠(CA) — Customer Admin & Front
- **한 줄 설명**: 크리에이터(강사/운영자)가 상품을 등록·관리하고, 일반 사용자가 프론트에서 수강·구매하는 교육 커머스 플랫폼
- **대상 사용자**: ① CA 관리자(크리에이터·운영 담당자), ② 일반 학습자(구매자)
- **핵심 가치 제안**: 다양한 강의 유형(라이브·화상·디지털 등)을 한 곳에서 등록·판매하고, 매출·정산까지 한눈에 확인

---

## 2. 테스트 환경
- **CA Admin URL**: https://customer-admin.solsol-dev.workers.dev/
- **Front URL**: https://customer-front.solsol-dev.workers.dev/
- **접근 방식**: 로그인 필요 (Admin) / 회원가입 후 로그인 (Front)
- **테스트 계정**:
  - CA 관리자: `nvrstop@gmail.com` / 비밀번호: `${ENV:CA_ADMIN_PASSWORD}`
  - 일반 유저: 테스트 중 신규 회원가입으로 생성 (이메일·비밀번호는 테스트 전 임의 지정)
- **지원 뷰포트**: PC(1440×900) 기준 / 모바일(390×844) 페르소나 해당 시 적용

---

## 3. 사전 조건 (Preconditions)
- CA Admin에 `nvrstop@gmail.com` 계정으로 정상 로그인이 가능해야 한다.
- Front 사이트가 접근 가능하고 회원가입 화면이 열려야 한다.
- 테스트 전 등록된 상품이 없는 깨끗한 상태를 권장하나, 기존 데이터가 있어도 새 상품 등록 후 구별 가능하면 무방하다.
- 실결제(PG 최종 승인) 및 실발송(SMS/메일 실발송)은 **수행하지 않는다**.

---

## 4. 테스트 태스크 (사용자 목표 단위)

> **공통 관찰 포인트**: 오류 메시지 명확성, 필수 입력값 안내, 저장 후 피드백(성공·실패 토스트/알림), 페이지 이동 흐름의 자연스러움, UX 일관성

---

### T0. 일반 유저 회원가입 (Front)
- **목표**: 일반 학습자로서 쏠쏠 프론트에 신규 회원가입을 완료한다.
- **시작 지점**: https://customer-front.solsol-dev.workers.dev/ 홈 화면
- **성공 기준**: 회원가입 완료 후 로그인 상태로 마이페이지 또는 홈에 진입할 수 있다.
- **관찰 포인트**: 가입 양식 항목 구성, 이메일 인증 여부, 오류 안내, 가입 완료 후 UX

---

### T1. 일반강의 상품 등록 → 프론트 노출 확인 → 구매 → 주문·정산 확인
- **목표**:
  1. (Admin) 일반강의 상품을 등록하고 판매 상태로 설정한다.
  2. (Front) 등록한 상품이 프론트에 정상 노출되는지 확인한다.
  3. (Front) 일반 유저가 해당 상품을 구매한다.
  4. (Admin) 주문 메뉴에서 해당 주문이 확인되고, 정산 내역에 반영되는지 확인한다.
- **시작 지점**: Admin — 상품 관리 > 일반강의
- **성공 기준**:
  - Admin에서 상품 등록 완료 메시지가 표시되고 목록에 상품이 보인다.
  - Front에서 해당 상품이 검색·탐색 가능하고 상세 페이지가 열린다.
  - Front 결제 흐름이 끝까지 진행되며 구매 완료 화면이 표시된다.
  - Admin 주문 메뉴에 해당 주문 건이 표시되고, 정산 내역에 금액이 반영된다.
- **관찰 포인트**: 상품 등록 필드 구성·필수값, 썸네일 업로드, 가격 입력, 노출 시점, 구매 후 주문 반영 속도

---

### T2. 라이브강의 상품 등록 → 프론트 노출 확인 → 구매 → 주문·정산 확인
- **목표**: 라이브강의 상품을 등록하고 T1과 동일한 전체 흐름(노출→구매→주문·정산)을 검증한다.
- **시작 지점**: Admin — 상품 관리 > 라이브강의
- **성공 기준**: T1 성공 기준과 동일 (상품 유형만 라이브강의)
- **관찰 포인트**: 라이브 일정(날짜·시간) 입력 필드, 정원 설정, 프론트에서 일정 정보 표시 여부

---

### T3. 화상강의 상품 등록 → 프론트 노출 확인 → 구매 → 주문·정산 확인
- **목표**: 화상강의 상품을 등록하고 전체 흐름을 검증한다.
- **시작 지점**: Admin — 상품 관리 > 화상강의
- **성공 기준**: T1 성공 기준과 동일 (상품 유형만 화상강의)
- **관찰 포인트**: 화상 링크(Zoom 등) 입력 방식, 일정 설정, 프론트 노출 형태

---

### T4. 디지털상품 등록 → 프론트 노출 확인 → 구매 → 주문·정산 확인
- **목표**: 디지털상품(파일·콘텐츠 다운로드 등)을 등록하고 전체 흐름을 검증한다.
- **시작 지점**: Admin — 상품 관리 > 디지털상품
- **성공 기준**: T1 성공 기준과 동일 (상품 유형만 디지털상품)
- **관찰 포인트**: 파일 업로드 방식, 용량 제한 안내, 구매 후 다운로드 링크 제공 여부

---

### T5. 패키지 상품 등록 → 프론트 노출 확인 → 구매 → 주문·정산 확인
- **목표**: 여러 상품을 묶은 패키지 상품을 등록하고 전체 흐름을 검증한다.
- **시작 지점**: Admin — 상품 관리 > 패키지
- **성공 기준**: T1 성공 기준과 동일 (상품 유형만 패키지)
- **관찰 포인트**: 구성 상품 선택 UI, 패키지 할인가 설정, 프론트에서 구성 상품 목록 표시 여부

---

### T6. 멤버십 상품 등록 → 프론트 노출 확인 → 구독 → 주문·정산 확인
- **목표**: 멤버십 상품을 등록하고 일반 유저가 구독(가입)하는 흐름을 검증한다.
- **시작 지점**: Admin — 상품 관리 > 멤버십
- **성공 기준**: T1 성공 기준과 동일 (상품 유형만 멤버십, 구매 대신 구독)
- **관찰 포인트**: 구독 주기(월·연) 설정, 자동결제 안내 문구, 구독 완료 후 혜택 노출 여부

---

### T7. 프리미엄커뮤니티 상품 등록 → 프론트 노출 확인 → 가입 → 주문·정산 확인
- **목표**: 프리미엄커뮤니티 상품을 등록하고 일반 유저가 유료 커뮤니티에 가입하는 흐름을 검증한다.
- **시작 지점**: Admin — 상품 관리 > 프리미엄커뮤니티
- **성공 기준**: T1 성공 기준과 동일 (상품 유형만 프리미엄커뮤니티)
- **관찰 포인트**: 커뮤니티 접근 권한 설정, 가입 후 커뮤니티 화면 진입 여부, 게시판 기능 기본 동작

---

### T8. 주문 관리 종합 확인
- **목표**: T1~T7에서 발생한 모든 주문 건이 Admin 주문 목록에 정확히 반영되어 있는지 일괄 확인한다.
- **시작 지점**: Admin — 판매 관리 > 주문
- **성공 기준**: 상품 유형별 7건 이상의 주문이 목록에 표시되고, 주문 상세에서 구매자·상품명·금액이 올바르게 보인다.
- **관찰 포인트**: 주문 검색·필터 기능, 상태값(결제완료·취소 등) 표기, 목록 페이지네이션

---

### T9. 정산 내역 확인
- **목표**: 구매 완료된 건들에 대한 정산 내역이 Admin에서 조회된다.
- **시작 지점**: Admin — 매출 및 정산관리 > 정산내역
- **성공 기준**: 상품별 매출 금액, 수수료, 정산 예정액이 표시되고 내역을 상세히 확인할 수 있다.
- **관찰 포인트**: 정산 주기·기준 안내, 금액 계산 정확성, 기간 필터 동작

---

### T10. 쿠폰 발급 및 할인 적용 (선택 심화)
- **목표**: Admin에서 할인 쿠폰을 발급하고, 일반 유저가 구매 시 쿠폰을 적용해 할인된 금액으로 결제한다.
- **시작 지점**: Admin — 판매 관리 > 쿠폰
- **성공 기준**: 쿠폰 코드가 생성되고, 프론트 결제 단계에서 쿠폰 적용 시 할인 금액이 반영된다.
- **관찰 포인트**: 쿠폰 조건(적용 상품·최소 금액·사용 기간) 설정, 프론트 쿠폰 입력 UI

# 통합테스트 시나리오 — QA 에이전트팀 콘솔

> 대상: http://localhost:5510/
> 비밀번호는 환경변수 QA_PASSWORD 로 주입 (파일에 직접 기재 금지)

---

## 1. 서비스 개요

- **서비스명**: QA 에이전트팀 콘솔
- **한 줄 설명**: 페르소나 기반 통합 QA 에이전트를 사내에서 운영·관리하는 웹 콘솔
- **대상 사용자**: 사내 QA 담당자, 프로젝트 관리자, 개발 운영 팀원
- **핵심 가치 제안**: 페르소나 AI 에이전트가 실제 브라우저를 구동해 사용자 테스트를
  자동으로 수행하고, 빈도·심각도 기반 통합 QA 리포트를 빠르게 산출한다

---

## 2. 테스트 환경

- **대상 URL**: http://localhost:5510/
- **접근 방식**: 비밀번호 단독 로그인 (세션 유지)
- **테스트 계정**: 비밀번호 = `${ENV:QA_PASSWORD}` (malgnqa)
- **지원 뷰포트**: PC(1440×900) 기준 / 모바일(390×844) 병행 확인

---

## 3. 사전 조건 (Preconditions)

- 서버가 http://localhost:5510/ 에서 정상 응답 중이어야 한다
- 테스트 시작 전 로그아웃 상태(또는 시크릿 탭)에서 시작한다
- 기존 프로젝트 데이터(구글 정산 시스템, QA에이전트 테스트, ProjA)가 존재하는 상태
- 실결제·실발송·데이터 영구 삭제 등 비가역 행위는 수행하지 않는다

---

## 4. 테스트 태스크 (사용자 목표 단위)

### T1. 로그인 — 비밀번호로 콘솔에 접근한다

- **목표**: 올바른 비밀번호를 입력해 콘솔 내부로 진입한다
- **시작 지점**: http://localhost:5510/ 최초 접속 (로그인 화면)
- **성공 기준**: 대시보드 화면이 표시되고, 사이드바의 메뉴(대시보드·페르소나 시드·
  프로젝트·설정)가 보인다
- **관찰 포인트**:
  - 잘못된 비밀번호 입력 시 오류 메시지가 명확하게 표시되는가
  - 빈 값 제출 시 적절한 안내가 나오는가
  - 로그인 후 리다이렉트가 올바른 페이지로 이루어지는가

---

### T2. 대시보드 — 전체 현황을 한눈에 파악한다

- **목표**: 대시보드에서 진행 중 실행 수, 미해결 P1 이슈, 이번 주 실행 수,
  전체 프로젝트 수를 확인하고 원하는 프로젝트로 이동한다
- **시작 지점**: 대시보드 (로그인 직후)
- **성공 기준**:
  - 요약 지표 4개 카드가 숫자와 함께 표시된다
  - 전체 프로젝트 카드 목록이 보이고 각 카드에서 실행 이력 요약을 볼 수 있다
  - 최근 실행 테이블에서 프로젝트·시나리오·상태·출시권고·P1·시작 시각이 표시된다
  - 테이블의 특정 행을 선택하면 실행 상세 화면으로 이동한다
- **관찰 포인트**:
  - 미해결 P1이 붉은색 강조로 표시되는가
  - 진행 중 실행이 있는 프로젝트와 이력 없는 프로젝트가 시각적으로 구분되는가

---

### T3. 페르소나 시드 — 기본 페르소나 목록을 열람한다

- **목표**: 시스템에 등록된 기본 페르소나 20인의 목록과 상세 정보를 확인한다
- **시작 지점**: 사이드바 "페르소나 시드" 메뉴
- **성공 기준**:
  - 페르소나 목록이 표시된다 (이름, 연령, 직업 등 속성 포함)
  - 개별 페르소나의 상세 속성(디지털 친숙도, 접근성 요구 등)을 확인할 수 있다
- **관찰 포인트**:
  - 고령·저친숙도·접근성 필요 페르소나가 목록에 포함되어 있는가
  - 페르소나 수가 인구통계 분포를 반영하는지 눈으로 확인 가능한가

---

### T4. 프로젝트 목록 — 전체 프로젝트를 탐색·검색한다

- **목표**: 프로젝트 목록에서 원하는 프로젝트를 검색하고, 숨겨진 프로젝트를
  표시·감추는 토글을 사용한다
- **시작 지점**: 사이드바 "프로젝트" 메뉴
- **성공 기준**:
  - 등록된 프로젝트가 서비스명·URL·담당 관리자·플랫폼·등록일 컬럼으로 표시된다
  - 검색창에 키워드를 입력하면 해당 프로젝트만 필터링된다
  - "숨기기 제외" 토글로 숨겨진 프로젝트 포함·제외가 전환된다
- **관찰 포인트**:
  - 검색어 입력 후 빈 결과일 때 안내 문구가 표시되는가
  - 숨기기/표시 버튼이 즉시 반응하는가

---

### T5. 새 프로젝트 등록 — 신규 테스트 대상 서비스를 등록한다

- **목표**: "새 프로젝트" 모달을 통해 테스트 대상 서비스를 새로 추가한다
- **시작 지점**: 프로젝트 목록 페이지
- **성공 기준**:
  - 서비스명·대상 URL·플랫폼·설명·담당 관리자를 입력하고 저장하면
    목록에 새 프로젝트가 나타난다
- **관찰 포인트**:
  - 필수 필드(서비스명, URL) 미입력 시 유효성 오류가 명확히 표시되는가
  - 잘못된 URL 형식 입력 시 안내가 있는가
  - 취소 버튼이 모달을 닫고 목록을 원래대로 유지하는가

---

### T6. 프로젝트 개요 탭 — 프로젝트 QA 현황을 파악한다

- **목표**: 특정 프로젝트의 개요 탭에서 총 실행 수, 미해결 이슈, Blocker/Major
  이슈 수, 세그먼트별 태스크 분석을 확인한다
- **시작 지점**: 대시보드 또는 프로젝트 목록에서 프로젝트 카드 선택
- **성공 기준**:
  - 4개 지표 카드(총 실행, 미해결 이슈, Blocker 이슈, Major 이슈)가 표시된다
  - 실행 이력이 없을 때 빈 상태 안내 문구가 보인다
- **관찰 포인트**:
  - "QA 실행" 버튼이 개요 탭에서도 접근 가능한가
  - 이슈 수가 붉은색·주황색 등 심각도 색상으로 구분되는가

---

### T7. 페르소나 배정 탭 — 프로젝트에 테스트 페르소나를 배정한다

- **목표**: 프로젝트의 타겟 고객층을 설명하고 AI를 통해 적합한 페르소나를
  추출·배정한다
- **시작 지점**: 프로젝트 상세 > "페르소나" 탭
- **성공 기준**:
  - 타겟 고객층 설명 입력 후 "풀에서 추출" 버튼을 누르면 페르소나 목록이 생성된다
  - 배정된 페르소나 수가 표시된다
- **관찰 포인트**:
  - 인원 수 입력 필드에 범위 밖 값(0, 음수, 초과값) 입력 시 처리가 적절한가
  - 타겟 설명 없이 추출 시 안내가 있는가

---

### T8. 시나리오 등록 및 편집 — QA 시나리오를 업로드하거나 새로 작성한다

- **목표**: 기존 .md 파일을 업로드하거나 새 시나리오를 AI 편집기로 작성·저장한다
- **시작 지점**: 프로젝트 상세 > "시나리오·실행" 탭
- **성공 기준**:
  - 파일 업로드 후 시나리오 목록에 파일명이 나타난다
  - "AI로 편집" 버튼을 통해 편집 화면으로 진입할 수 있다
  - "보기" 버튼으로 시나리오 내용을 읽을 수 있다
- **관찰 포인트**:
  - 지원하지 않는 파일 형식 업로드 시 오류 안내가 있는가
  - 이미 동일 파일명 시나리오가 있을 때 어떻게 처리되는가

---

### T9. QA 실행 — 선택한 시나리오로 QA를 시작한다

- **목표**: 시나리오를 선택하고 QA 실행을 시작해 진행 상태를 확인한다
- **시작 지점**: 프로젝트 상세 > "시나리오·실행" 탭 > 실행 섹션
- **성공 기준**:
  - 시나리오 선택 후 "실행" 버튼을 누르면 실행이 시작되고 상태가 "실행중"으로 바뀐다
  - 대시보드의 "진행 중 실행" 카운트가 증가한다
- **관찰 포인트**:
  - 시나리오 미선택 상태에서 실행 버튼이 비활성화되거나 안내가 표시되는가
  - 동시 실행 한도(설정 페이지에 표시된 값) 초과 시 어떻게 안내하는가
  - 실행 목록에 새 실행 행이 즉시 추가되는가

---

### T10. 실행 결과 상세 — 통합 QA 리포트를 열람한다

- **목표**: 완료된 실행의 상세 리포트(통합 분석, 이슈 목록, 출시 권고)를 확인한다
- **시작 지점**: 대시보드 최근 실행 테이블 또는 시나리오·실행 탭의 실행 이력
- **성공 기준**:
  - 실행 결과 화면에서 출시 권고(🟢 권고 / 🟡 조건부 / 🔴 비권고)가 표시된다
  - P1(Blocker·Major) 이슈 목록이 표시된다
  - 개별 페르소나별 리포트를 확인할 수 있다
- **관찰 포인트**:
  - "실행중" 상태의 실행을 클릭했을 때 진행 중 화면이 나오는가
  - 리포트 내 이슈가 심각도(P0/P1/P2/P3) 순서로 정렬되는가
  - 브레드크럼(프로젝트 > 실행명)이 올바르게 표시되는가

---

### T11. QA 리스트 — 프로젝트 전체 이슈를 필터링·검색한다

- **목표**: 프로젝트에 누적된 QA 이슈를 검색하고 저장한다
- **시작 지점**: 프로젝트 상세 > "QA 리스트" 탭
- **성공 기준**:
  - 이슈 목록이 표시되고 키워드·페르소나·시나리오로 검색·필터가 동작한다
  - "저장하기" 버튼으로 현재 목록을 내보낼 수 있다
- **관찰 포인트**:
  - 이슈가 없을 때 빈 상태 안내가 있는가
  - 필터 조합(복수 조건)이 올바르게 동작하는가

---

### T12. 프로젝트 설정 — 서비스 정보와 알림 수신자를 관리한다

- **목표**: 프로젝트 설정에서 서비스명·URL·금지 영역을 수정하고, 알림 이메일을
  추가·삭제한다
- **시작 지점**: 프로젝트 상세 > "설정" 탭
- **성공 기준**:
  - 서비스명·URL·플랫폼·설명·담당자·금지 영역을 수정하고 저장하면 변경이 반영된다
  - 알림 수신자 이메일을 추가하면 목록에 나타나고, 삭제하면 제거된다
- **관찰 포인트**:
  - 필수 필드를 비우고 저장 시 유효성 오류가 표시되는가
  - 유효하지 않은 이메일 형식 입력 시 안내가 있는가
  - "페르소나 미설정 시 현재 수정된 프로젝트만 실행 가능합니다" 경고가 언제 표시되는가

---

### T13. 접속자 관리 — 관리자 계정을 추가·수정한다

- **목표**: 새 관리자를 추가하고 비밀번호를 변경하는 흐름을 완료한다
- **시작 지점**: 사이드바 하단 "접속자 관리" 링크
- **성공 기준**:
  - "관리자 추가" 버튼으로 새 관리자명과 이메일(슬랙)을 입력하고 저장하면
    목록에 나타난다
  - "비밀번호 변경" 버튼으로 해당 관리자의 비밀번호를 변경할 수 있다
- **관찰 포인트**:
  - 이미 존재하는 관리자명·이메일 입력 시 중복 안내가 있는가
  - 관리자 삭제 시 확인 절차(재확인 다이얼로그 등)가 있는가
  - 담당 프로젝트가 있는 관리자 삭제 시 경고 문구가 표시되는가

---

### T14. 로그아웃 — 세션을 종료한다

- **목표**: 로그아웃 버튼을 통해 세션을 안전하게 종료한다
- **시작 지점**: 사이드바 하단 "로그아웃" 버튼
- **성공 기준**: 로그인 화면으로 이동하고 이전 화면 URL로 직접 접근하면
  로그인 화면으로 리다이렉트된다
- **관찰 포인트**:
  - 로그아웃 후 브라우저 뒤로가기로 콘솔 내부 화면에 접근할 수 없는가

---

## 6. 제외 범위 (Out of scope)

- 실제 QA 에이전트 실행 완료까지의 전체 대기 (실행 시작 여부만 확인)
- Playwright MCP 연동 내부 동작 검증
- 데이터베이스 직접 조작 또는 API 레벨 테스트
- 보안 침투 테스트 (SQL Injection, XSS 등)
- 페르소나 AI 생성 결과의 품질 평가 (UX 흐름만 확인)

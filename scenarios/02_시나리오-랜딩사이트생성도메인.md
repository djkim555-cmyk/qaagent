## 1. 서비스 개요

- **서비스명**: 쏠쏠(solsol) 브랜드사이트 — CreatorLMS 브랜드 사용자단
- **한 줄 설명**: YouTube 크리에이터가 자기 이름의 온라인 강의 사이트(LMS)를 만들고 플랜을 구독하는 **브랜드/가입/사이트 개설 사이트**.
- **대상 사용자**: 유료 멤버십·강의를 운영하려는 개인 크리에이터와 소규모 교육 사업자. **웹서비스 개설 경험이 없는 사람이 다수**(도메인·슬러그 개념 생소).
- **핵심 가치 제안**: "내 브랜드 주소(`https://{내도메인}.solsol.live`)로 된 강의 사이트를, 개발자 없이 몇 분 만에 개설한다."
- **묶음 ②가 검증하는 것**: 방문자가 랜딩에서 **이 서비스가 무엇인지 이해 → 시작 지점을 찾아 → 첫 사이트를 실제로 개설**하기까지의 전환 동선과, 그 결과물(사이트 목록·개설 메일)이 정확히 보이는가.

## 2. 테스트 환경

- **대상 URL**: `https://solsol-brand.pages.dev/`
  - ⛔ **실행 전 반드시 확인**: 이 URL은 **`config/target.json`의 `baseUrl`과 일치해야 한다.** 그러나 **2026-07-28 실측 기준 현재 config는 다른 서비스(`http://localhost:8000` — "구글 파트너 정산")를 가리키고 있다**(`00_INDEX §5 B-1`). **config가 solsol-brand를 가리키도록 설정되기 전에는 이 시나리오를 실행하지 않는다** — 실행하면 전 페르소나가 엉뚱한 앱을 테스트하고 `guards`의 정지선 12항도 작동하지 않는다. (이전 판(v1.0)이 "config의 baseUrl과 일치"라고 단정한 것은 사실이 아니었다.)
- **접근 방식**: 랜딩·LP·약관은 **공개** / `/my/**`(내 사이트)는 **로그인 필요** — 비로그인 접근 시 `/login?next=<원경로>`로 리다이렉트(전수 실측).
- **테스트 계정**: `/login` 하단 **"⚠ 임시 검수용 로그인 — 운영 로그인 아님"** 섹션의 계정 버튼(10개) 사용. **계정 이메일·비밀번호를 리포트에 절대 기재하지 않는다**(정지선 #11).
  - **사이트 0개 계정(9개)**: 검수 리뷰어 / 디제 / 겸겸 / 희망 / 제리 / 뿌꾸 / 윤희 / 검수 / 미니 → **빈 상태·사이트 생성 시나리오**에 배정. **이 9개가 곧 "사이트 생성 슬롯 9개"**다(정지선 #10, T13 참조).
  - **사이트 1개 보유 계정(1개)**: **도탑**("쏠쏠한 도탑" / `dotype.solsol.live` / FREE / 배지 "개설 중") → **보유 상태 목록 시나리오**에 배정. **도탑 계정에서는 사이트를 추가 생성하지 않는다.**
- **지원 뷰포트**: 모바일 390×844 / PC 1440×900 — 페르소나 기기대로. **모바일 페르소나는 T2·T7·T13·T18을 반드시 모바일로 수행**(헤더 CTA·폼 세로 스택 관찰).
- **페르소나별 고유 도메인 규칙(충돌 방지, 필수)**: 사이트 생성·중복 체크에 쓰는 도메인은 **`qa-<페르소나ID 소문자>-<두자리 숫자>`** 형태로만 만든다(예: `qa-p07-01`). 여러 페르소나가 같은 문자열을 쓰면 뒤 사람이 불필요하게 "이미 사용 중" 결과를 맞는다.

## 3. 사전 조건 (Preconditions)

1. 브라우저 캐시·세션 초기화 상태에서 **비로그인으로 랜딩(`/`)부터 시작**한다(T1~T6은 비로그인).
2. T7 이후는 검수용 로그인 버튼으로 배정 계정에 로그인한다. 로그인 성공 시 **`/my/sites`로 자동 착지**한다(10계정 공통 실측).
3. **사이트를 이미 1개 만든 계정으로는 T13(생성 완주)을 다시 수행하지 않는다** — 정지선 #10.
4. 콘솔 로그를 켜 둔다. 비로그인 전 화면에서 `POST /api/session/refresh` **401**이, 로그인 후 화면에서 **"Hydration completed but contains mismatches."** 경고가 상시 발생한다(실측) — **이미 알려진 현상이므로 신규 이슈로 올리지 말고 "관찰됨"으로만 기록**한다.
5. 아래 6개 빨간 배지·문구는 **의도된 개발 단계 표식**이다(결함 아님). 페르소나는 "버그"가 아니라 **"이게 사용자 신뢰도에 어떻게 읽히는가"**로 기록한다.
   `사용량 미연동`(사이트 카드) · `저장 미구현` · `EP 미비` · `스테이징(실 카드인증 비활성)` · `결제 전 예상치` · `⚠ 임시 검수용 로그인`
6. **★ 이미 고쳐진 결함 4건은 "찌를 대상"이 아니다(v1.1 신설)**: `RSK-004`(목록 백지 렌더) · `RSK-005`(라우팅 충돌) · `RSK-006`(enterprise 크래시) · `RSK-007`(저장용량 단위)은 **2026-07-28 수정·배포 완료 + 실사이트 실측으로 정상 동작이 확인**됐다(`02b §5-1`). 이 문서에서 해당 항목은 **`[재현]`이 아니라 `[회귀 스모크]`**다 — **정상 동작이 기본값이고, 이상이 보일 때만 캡처해 재발로 보고**한다. 원칙적으로 세션 시작 전 `qa-lead`의 P0 스모크 1회로 판정되며(`00_INDEX §4-2`), 페르소나는 그 결과를 전달받은 상태에서 자기 화면에서의 재발 여부만 부수적으로 본다.
7. **메일 관련 태스크(T14·T16)의 전제(v1.1 정정)**: 메일 발송 상태는 **원장 내부에서 충돌**한다 — 구 기록은 "brand-api 발송 로직 전건 TODO", 최신본(`BR01-r05.md:98`, 2026-07-28)은 **"메일 발송 스텁 + 트리거 10건 배선 완료"**. 따라서 **"온다/안 온다"를 전제하지 않는다.** 발송을 유발하는 액션 뒤에 **수신 여부를 관측해 사실로 기록**하고, 판정은 `[미확정]`으로 열어 둔다. **실발송 가능성이 있으므로 정지선 #9(동일 주소 기준 시나리오당 2회)를 엄격히 적용**한다.

### T5. 서비스 공지·업데이트 소식을 찾아본다 `[관측 전용 — 판정 없음]` `[미확인 · won't-fix]`
- **목표**: "서비스에 최근 무슨 변화가 있었는지"(공지·업데이트 소식)를 확인할 곳을 찾는다.
- **시작 지점**: 홈(`/`) — 헤더·푸터·고객센터 어디서든 자유롭게 탐색.
- **성공 기준**: **판정하지 않는다.** 아래 사실만 기록하면 태스크 완료다.
  - ① 공지·소식으로 보이는 진입점을 **찾았는가/못 찾았는가**(찾았다면 어디에서).
  - ② 그 진입점을 눌렀을 때 **목록 화면에 도달했는가**(도달했다면 URL과 화면 내용을, 못 했다면 무슨 일이 일어났는지).
  - ③ 목록에 도달한 경우에만 상세 글까지 열어 본다.
- **관찰 포인트**:
  - 실사이트 푸터의 **"업데이트 소식"이 `#` 죽은 링크**(실측)이고, `/notice` 경로는 **404**였다(실측). 설계 문서상 이 화면들은 **오너가 범위 제외(won't-fix)로 결정**한 항목이라 **"공지가 없다"를 결함으로 단정하지 않는다.**
  - 대신 **"사용자가 공지를 찾다가 어디까지 헤맸는가"**(클릭 횟수·경유 화면·최종 포기 지점)를 기록한다 — 이것이 이 태스크의 실제 산출물이다.
  - **저친숙 사용자가 막힐 지점**: 공지를 못 찾으면 문의하기로 가는가, 그냥 이탈하는가.
- **커버 화면ID**: `S-BR01-0501-001`(도달 여부만) · `S-BR01-0501-002`(도달 시에만)
- **관련 규칙**: 02 문서 §3-1 "`0501-001/002` won't-fix — 검증 대상 아님(오너 범위 제외, 2026-07-09)"
- **정지선**: **해당 없음** — 탐색·열람만. 404가 떠도 URL을 바꿔가며 경로를 추측 입력하지 않는다(서버 가드 우회 인접 행위, 정지선 #5 정신).

### T6. 랜딩·가격 화면에서 "시작하기"를 눌러 실제 시작 지점까지 간다 `[재현]`
- **목표**: 서비스를 쓰기로 마음먹은 사람이 **화면에 보이는 시작 버튼을 눌러 실제로 시작 절차에 진입**한다(무료로 시작 / 유료 플랜 구매 둘 다 시도).
- **시작 지점**: 비로그인 상태의 홈(`/`) 히어로 및 가격 페이지(`/pricing`).
- **성공 기준**: 각 CTA를 누른 뒤 **최종 착지 화면의 주소와 제목을 기록**했고, "내가 하려던 일(무료 시작 / 유료 구매)이 그 화면에서 이어지는가"를 판정했다. 무료 경로는 최소한 **로그인 또는 회원가입 화면에 도달**하면 성공.
- **관찰 포인트**:
  - `[재현]` **유료 CTA 오배선 — 랜딩→전환 동선의 단절**: 가격 페이지의 **"구매하기" 3개가 전부 `/login?next=/my/sites`**로 걸려 있어(실측, 로그인 상태에서도 동일), 클릭하면 **구매 화면이 아니라 "내 사이트 관리"로 착지**한다. 페르소나는 **"돈을 내려고 눌렀는데 어디에 도착했는가", "여기서 결제를 어떻게 하면 되는지 알겠는가"**를 그대로 기록한다.
    > **범위 주의**: 결제 화면(`/purchase`) 자체의 검증은 **묶음 ③ 소관**이다. 이 태스크는 **"전환 동선이 끊기는가"까지만** 보고, 결제 화면 안으로 들어가 검증하지 않는다. URL을 직접 입력해 `/purchase`에 진입하지 않는다.
  - `[재현]` **같은 이름 버튼이 서로 다른 곳으로 간다**: "무료로 시작하기"가 헤더에서는 `/login`, 히어로·하단에서는 `/my/sites`, 가격 카드에서는 `/signup`으로 실측됐다. 페르소나가 **어느 버튼을 눌렀느냐에 따라 다른 화면에 도착하는 것을 인지하는가**.
  - `[재현]` **로그인한 뒤에도 헤더에 "무료로 시작하기"가 그대로 노출**된다(모바일에서는 헤더 최상단 차지) — T7 이후 다시 확인한다.
    > **★ 주관 지정(v1.1)**: **"로그인 후에도 비로그인용 헤더 CTA가 유지되는 현상"의 주관 태스크는 이 T6**이다(01 T9·T15 / 03 §2·T2 / 05 E3에도 같은 관측이 흩어져 있어 1곳으로 모았다). **다른 태스크·다른 문서에서는 "사용자가 그 CTA를 보고 무엇을 했는가"만 기록**하고 현상 자체를 다시 보고하지 않는다.
  - **저친숙 사용자가 막힐 지점**: 로그인 화면으로 튕겨 나왔을 때 **"나는 계정이 없는데 왜 로그인 화면이지?"**에서 멈추는가, 아래 "회원가입하기"를 찾아내는가.
- **커버 화면ID**: `S-BR01-0101-001`(전환 CTA 동선)
- **관련 규칙**: 인벤토리 §4 blocker "가격 유료 CTA `/login?next=/my/sites` 오배선(상)" · RSK-002 · RSK-014(Free CTA 로그인 미분기)
- **정지선**: 결제·구매 화면에서는 **어떤 제출 버튼도 누르지 않는다**(정지선 #1). 이 태스크는 착지 지점 확인까지다.

### T7. 로그인 직후 "이제 뭘 해야 하는지"를 빈 화면에서 알아낸다
- **목표**: 사이트가 하나도 없는 신규 사용자가 **다음에 할 일(사이트 만들기)을 스스로 찾는다.**
- **시작 지점**: 검수용 로그인으로 **사이트 0개 계정**(검수 리뷰어/디제/겸겸/희망/제리/뿌꾸/윤희/검수/미니 중 배정된 1개) 로그인 → 자동 착지한 `/my/sites`.
- **성공 기준**: 빈 상태 안내("사이트가 하나도 없네요" / "아직 만들어진 사이트가 없어서 좀 쓸쓸하네요")를 읽고 **"+ 내 사이트 만들기"를 스스로 찾아 눌러 사이트 만들기 화면에 도달**한다.
- **관찰 포인트**:
  - 빈 상태 문구의 **캐주얼한 톤**("텅... 비어있어요...", "좀 쓸쓸하네요")을 페르소나가 어떻게 받아들이는가 — **연령·친숙도별 수용도 차이**(고령·업무 목적 페르소나에게 가볍게 읽히는가).
  - 빈 상태 화면에 **안내 카드 + 빈 블록이 중복**으로 두 번 나오는 느낌인가(설계상 `.sites-cta` + `.sites-empty` 2블록).
  - 하단 배너 "다른 플랜 둘러보기 → 플랜 둘러보러 가기"가 **사이트도 없는 시점에 유용한가/혼란스러운가**.
  - `[재현]` 로그인 후에도 헤더 "무료로 시작하기"·"문의하기(`/login?next=/inquiry`)"가 **비로그인용 그대로**인가(실측). → **주관은 T6.** 여기서는 그것을 본 뒤 **사용자가 무엇을 했는지**만 적는다.
  - `[회귀 스모크]` **목록 백지 렌더(RSK-004)** — 이 결함은 **2026-07-28 수정·배포 완료이고 실사이트 실측으로 정상 렌더가 확인**됐다(`02b §5-1`). **따라서 "정상적으로 빈 상태 문구가 보이는 것"이 기본값**이며, 이 항목은 재발 감시일 뿐이다. **콘텐츠 영역이 문구조차 없이 통째로 하얗게 뜰 때만** 즉시 캡처해 **"회귀 재발"**로 보고한다.
  - **저친숙 사용자가 막힐 지점**: "사이트"라는 말이 무엇을 뜻하는지(내 강의 홈페이지) 이해하는가.
- **커버 화면ID**: `S-BR01-0401-002`(빈 상태)
- **관련 규칙**: BR-R-068(빈 문구 분기) · **RSK-004 `[회귀 스모크]`**(목록 화면 백지 렌더 — **수정·배포 완료(`c0a0954`) 확인됨**, 재발 시에만 보고)
- **정지선**: **해당 없음** — 빈 상태 열람과 "+ 내 사이트 만들기" 화면 진입까지. **여기서 생성을 제출하지 않는다**(생성 완주는 T13, 정지선 #10).

### T8. 사이트 만들기 화면에서 아무것도 입력하지 않고, 또 너무 짧게 입력해 본다
- **목표**: 폼을 처음 만난 사람이 **무엇을 어떻게 입력해야 하는지** 안내를 통해 알아낸다(오류를 통해 배우는 과정 포함).
- **시작 지점**: `/my/sites` → "+ 내 사이트 만들기"(`/my/sites/create`).
- **성공 기준**: 아래 3가지를 모두 확인했다.
  1. **빈 채로 생성 시도** → "사이트 이름을 입력해 주세요" / "사이트 도메인을 입력해 주세요"가 **해당 필드마다** 표시된다.
  2. **이름 1자·도메인 2자 입력 후 생성 시도** → "사이트 이름은 2~20자 이내로 입력해 주세요" / "사이트 도메인은 3~30자 이내로 입력해 주세요"가 표시된다.
  3. **도메인을 비운 상태에서는 "도메인 중복 체크" 버튼이 눌리지 않는다**(비활성).
- **관찰 포인트**:
  - 오류가 났을 때 **어느 필드가 왜 틀렸는지 즉시 알 수 있는가**. `[재현]` 이 화면은 **에러 아이콘이 없는 8개 폼 중 하나**(앱 전체에서 `password-reset`만 아이콘 보유) — 글자만으로 충분한가.
    > **★ 주관 지정(v1.1)**: **폼 에러아이콘(D09/RSK-012)의 8개 폼 전수 대조는 `05 C4`가 주관**한다(5개 문서 10개 태스크가 각자 부분 기록해 통합 시 산발 보고되던 것을 정리). **여기서는 "이 화면의 오류 표현이 이 사용자에게 통했는가"만 기록**하고, 다른 폼과의 대조표를 만들지 않는다.
  - 20자·30자 상한을 **입력 중에 알려주는가**(입력창이 그냥 막히는가, 제출해야 알려주는가).
  - 이름과 도메인의 **차이를 이해하는가**("사이트 이름 = 사람이 읽는 제목 / 도메인 = 주소").
  - **저친숙 사용자가 막힐 지점(이 묶음 최대 난관)**: "도메인"이라는 말 자체. 앞의 `https://`와 뒤의 `.solsol.live`가 **고정이라는 걸 아는가**, 아니면 `https://`까지 직접 타이핑하려 하는가.
- **커버 화면ID**: `S-BR01-0401-001`
- **관련 규칙**: BR-R-021(이름 2~20자) · BR-R-023(도메인 클라 3~30자) · BR-R-025(미입력 시 중복체크 비활성) · D09(폼 에러아이콘 부재 — **전수 대조 주관은 05 C4**)
- **정지선**: **해당 없음** — 검증 오류를 유발하는 제출 시도까지만. **형식이 올바른 상태로 [+ 생성하기]를 눌러 실제 생성을 완료하지 않는다**(생성 완주는 T13, 계정당 1회·정지선 #10).

### T9. 한글·대문자·특수문자로 도메인을 만들어 본다(형식 위반)
- **목표**: 사용자가 **자기가 원하는 이름**(예: 한글 채널명, 대문자 브랜드명)을 도메인에 그대로 넣으려다 규칙을 알게 된다.
- **시작 지점**: `/my/sites/create` 도메인 입력 필드.
- **성공 기준**: 아래 입력들을 시도하고 **각각 어떻게 막히는지(또는 막히지 않는지)** 기록했다.
  1. 한글(예: `내채널`) → "영문 소문자·숫자·하이픈만 사용할 수 있어요(하이픈으로 시작/종료 불가)" 계열 안내가 나온다.
  2. 대문자 포함(예: `QA-Test-01`) → 막히거나 자동 소문자 변환된다(**어느 쪽인지 기록**).
  3. 특수문자(예: `qa_test!`), 하이픈으로 시작/종료(예: `-qatest`, `qatest-`).
  4. **31자 이상 50자 이하**의 긴 도메인(예: `qa-` + 30자) → 클라이언트가 막는가(설계상 클라 30자 / 서버 50자 **불일치**).
- **관찰 포인트**:
  - 안내 문구가 **무엇을 고치라는 것인지** 알려주는가(규칙 나열 vs 수정 예시 제시).
  - 대문자·공백처럼 **흔한 실수**에 대해 자동 보정(소문자 변환·하이픈 치환)을 해 주는가.
  - 오류 문구가 **입력 중** 뜨는가 **버튼을 눌러야** 뜨는가 — 반복 실패 횟수를 센다.
  - **저친숙 사용자가 막힐 지점**: 자기 채널명이 한글인 사람은 여기서 **무엇을 넣어야 할지 모른다.** 몇 번 만에 포기하는지, 예시가 있으면 도움이 될지 기록.
- **커버 화면ID**: `S-BR01-0401-001`
- **관련 규칙**: BR-R-022(SLUG_PATTERN) · BR-R-023(클라 3~30자 vs 서버 3~50자 불일치) · RSK-021
- **정지선**: **#5(서버 가드 우회)** — 클라이언트 검증이 막는 값을 **개발자도구·API 직접 호출로 우회해 제출하지 않는다.** 클라 30자 / 서버 50자 불일치는 **문서 인용까지만** 하고 재현하지 않는다. 리포트에 **"우회 미시도"**를 명시한다.

### T10. 쓰고 싶은 주소를 쓸 수 있는지 미리 확인한다 — "사용 가능" 결과 모달
- **목표**: 원하는 도메인이 **비어 있는지 미리 확인**하고 안심하고 다음 단계로 간다.
- **시작 지점**: `/my/sites/create`에서 **본인 전용 도메인**(`qa-<페르소나ID>-<두자리>`)을 입력한 뒤 **"도메인 중복 체크"를 클릭**해 모달을 띄운다.
- **성공 기준**: 모달에 **체크 아이콘 + "사용 가능한 도메인입니다" + `https://qa-<...>.solsol.live`**가 표시되고, [확인]으로 닫으면 **입력값이 그대로 유지**된다.
- **관찰 포인트**:
  - 모달의 미리보기 주소가 **`.solsol.live`**인가(`.solsol.com`이면 구 표기).
  - "사용 가능"을 본 사용자가 **"이제 확정된 것"으로 오해하는가** — 실제로는 **생성 제출 시점에 서버가 다시 판정**하고 그 사이 타인이 선점할 수 있다(설계상 의도). **그런 안내가 화면에 있는가**를 본다.
  - [확인] 외에 **Esc·✕·바깥 클릭**으로 닫히는가 / 모달이 열린 동안 **뒤 배경이 스크롤되는가** / 닫은 뒤 **포커스가 원래 버튼으로 돌아오는가**(`[재현]` 앱 전체에 포커스 트랩·복귀 미구현).
    > **★ 문서 간 정합(v1.1)**: **모달 접근성(포커스 트랩·복귀·Esc·배경 스크롤 잠금)의 표준 판정은 `05 B3`이 정본**이며, 이 도메인 중복확인 모달은 **05 B3의 5종 중 1순위 대상**이다(실물에서 실제로 열 수 있는 몇 안 되는 모달, `02b §5-7`). **여기서는 페르소나가 "닫으려다 어떻게 헤맸는가"라는 체감만 기록**하고 WCAG 합격/불합격은 판정하지 않는다. 결과가 갈리면 **05를 정본으로 한다.**
  - 같은 도메인으로 **중복 체크를 여러 번 반복**해도 동일하게 동작하는가(정지선 #10에 따라 **중복 체크는 자유롭게 반복 가능**).
  - **저친숙 사용자가 막힐 지점**: "중복 체크"를 **누르지 않고도 생성될 것**이라 생각하는가(T12로 이어짐).
- **커버 화면ID**: `S-BR01-0401-001_pu01`
- **관련 규칙**: BR-R-024 · BR-R-026(서버 재확정) · BR-R-027(`.solsol.live`) · BR-R-077(모달 공통 a11y — **판정 주관 05 B3**) · RSK-021
- **정지선**: **#10(부분)** — **도메인 중복 체크는 자유롭게 반복 가능**하다(정지선 원문이 명시적으로 허용). 다만 여기서 **[+ 생성하기]는 누르지 않는다**(생성은 T13에서 계정당 1회).

### T11. 남이 이미 쓰는 주소를 넣어 본다 — "사용 중" 결과 모달
- **목표**: 원하는 주소가 이미 쓰이고 있을 때 **무엇을 해야 하는지 알아낸다.**
- **시작 지점**: `/my/sites/create` 도메인 필드에 **이미 존재하는 도메인 `dotype`** 입력 → "도메인 중복 체크" 클릭.
- **성공 기준**: 모달에 **close(✕) 아이콘 + "이미 사용 중인 도메인입니다" + "다른 도메인을 선택해 주세요 — https://dotype.solsol.live"**가 뜨고, 닫은 뒤 **도메인 입력 필드에도 "이미 사용 중인 도메인입니다." 인라인 오류**가 남는다.
- **관찰 포인트**:
  - "사용 가능"(T10)과 **아이콘·색·문구가 확실히 구분**되는가 — 대충 보고 성공으로 오해할 여지가 있는가.
  - 사용자가 **다음에 무엇을 해야 하는지** 알 수 있는가(대안 도메인 제안이 있는가, 없는가).
  - 모달을 닫은 뒤 인라인 오류가 **언제 사라지는가**(다시 입력하면 즉시 사라지는가, 남아서 헷갈리는가).
  - 네트워크가 불안정할 때(개발자도구 없이 재현 어려우면 생략) 폼 전체 오류로 떨어지는가 — **`[미확인]`이면 그대로 표기**.
  - **저친숙 사용자가 막힐 지점**: "이미 사용 중"이 **내 잘못**이라고 느끼는가, 서비스 문제라고 느끼는가.
- **커버 화면ID**: `S-BR01-0401-001_pu02`
- **관련 규칙**: BR-R-024 · BR-R-027 · BR-R-077(모달 공통 a11y — **판정 주관 05 B3**) · RSK-021
- **정지선**: **#10(부분)** — 중복 체크 반복은 자유. **타인 소유 도메인(`dotype`)으로 생성 제출을 시도하지 않는다**(선점·오염 방지). **#11** — 도탑 계정의 실제 주소는 화면에 보이는 그대로만 인용하고 자격값은 기재하지 않는다.

### T12. 중복 확인을 건너뛰고, 약관에 동의하지 않은 채로 만들어 본다
- **목표**: 절차를 잘 모르는 사용자가 **바로 생성 버튼부터 누른다.** 서비스가 이를 어떻게 막고 안내하는지 확인한다.
- **시작 지점**: `/my/sites/create`에 **이름·도메인은 형식에 맞게 채우되**, ① 도메인 중복 체크를 **누르지 않은 상태**, ② 무료약정상품 구매 약관에 **동의하지 않은 상태**로 "+ 생성하기"를 시도한다.
- **성공 기준**: 아래 ①은 **`[관측 전용 — 판정 없음]`**, ②는 **합격/불합격/`[미확인]` 3값 판정** 대상이다(v1.1에서 분리 — 이전 판은 둘을 "생성이 진행되지 않는다"는 하나의 합격선으로 묶어 ①의 결과가 자동 불합격으로 찍힐 소지가 있었다).
  - ① **`[관측 전용]`** 중복 확인 없이 눌렀을 때: 막히는가, 그냥 생성이 진행되는가 — **둘 중 무엇인지 사실만 기록한다.** 설계상 최종 판정은 서버 몫이라 **통과하는 것도 설계일 수 있다**(`[추정]`) → **어느 쪽이든 결함으로 단정하지 않는다.**
    - ⚠️ **생성이 실제로 진행된 경우**: 그 시점에 **정지선 #10의 계정당 1회 슬롯을 소진**한 것이다 → 즉시 기록하고 **T13을 별도로 수행하지 않는다.**
  - ② **약관 미동의 시 생성이 차단되는가** — **차단되면 합격 / 차단되지 않으면 불합격**(BR-R-028: 무료도 약관 동의 필수). **단 차단 "문구"는 설계 문서에 명시가 없어 `[미확인]`** — 문구는 그대로 인용해 기록하되 **"이 문구가 맞다/틀리다"는 판정하지 않는다.**
- **관찰 포인트**:
  - 약관 링크(`>`)를 눌러 **약관 상세 모달**이 뜨는가(공유 모달 `C01` — **주관은 묶음 ①**, 여기서는 **뜨는지 여부만** 확인하고 본문 검증은 하지 않는다).
  - 무료 플랜인데 **"무료약정상품 구매 약관"에 동의해야 하는 것**을 사용자가 납득하는가.
  - 차단 후 **포커스가 부족한 항목으로 이동**하는가, 사용자가 스스로 찾아야 하는가.
  - **저친숙 사용자가 막힐 지점**: 화면 아래쪽 체크박스를 **못 보고** "왜 안 만들어지지"를 반복하는가.
- **커버 화면ID**: `S-BR01-0401-001`
- **관련 규칙**: BR-R-026(제출 시 서버 `ALREADY_EXISTS` 재확정) · BR-R-028(무료도 약관 동의 필수, 차단 문구 `[미확인]`)
- **정지선**: **#10** — ①의 "중복 확인 없이 생성 시도"에서 **생성이 실제로 진행되면 그 시점이 곧 T13의 1회 슬롯을 소진한 것**이다. 그 경우 **T13을 다시 수행하지 않고**, 이 태스크의 결과를 T13의 완주 기록으로 승계한다(계정당 생성 총 1회 불변).

### T13. 내 강의 사이트를 실제로 하나 만든다(계정당 1회) — 그리고 목록에서 확인한다
- **목표**: 첫 사이트를 **끝까지 개설**하고, 만들어진 결과를 내 사이트 목록에서 확인한다.
- **시작 지점**: `/my/sites/create` (사이트 0개 계정, 앞 태스크에서 형식·중복 확인을 마친 상태).
- **성공 기준**: 생성 후 **사이트 목록(`/my/sites`)에 방금 만든 사이트 카드가 나타나고**, 카드에 **사이트 이름과 `qa-<...>.solsol.live` 주소**가 표시된다.
- **★ 수행 조건 — 생성 슬롯(v1.1 신설)**: 사이트를 만들 수 있는 계정은 **사이트 0개 계정 9개뿐**이고 정지선 #10이 **계정당 1회**로 묶으므로, **이 서비스 전체에서 생성 완주는 최대 9회**다. 묶음 ② 배정 인원이 9명을 넘거나 앞선 웨이브가 슬롯을 이미 소진했다면:
  - **자기 배정 계정에 이미 사이트가 있으면(= 슬롯 소진) T13을 수행하지 않는다.** 결과는 **"미완주(슬롯 소진)"**로 기록한다 — `[미확인]`이나 실패가 아니라 **설계된 미수행**이다.
  - 이 경우에도 **T8·T9·T12(폼 검증)까지는 그대로 수행**한다(생성 제출 직전까지가 이 묶음의 주 관측 대상이므로 손실이 크지 않다).

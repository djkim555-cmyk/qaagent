# 통합테스트 시나리오 — 온라인 쇼핑몰 (예시)

> 양식 사용법을 보여주기 위한 예시입니다. 실제 테스트 시 이 파일을 참고해 새 시나리오를 작성하세요.

---

## 1. 서비스 개요
- **서비스명**: 마이샵 (가상의 의류 쇼핑몰)
- **한 줄 설명**: 20~50대 대상 의류·잡화 온라인 쇼핑몰
- **대상 사용자**: 모바일로 옷을 구매하는 일반 소비자
- **핵심 가치 제안**: 빠른 검색과 간편 결제

## 2. 테스트 환경
- **대상 URL**: https://staging.myshop.example.com
- **접근 방식**: 스테이징 (로그인 필요)
- **테스트 계정**: config/target.json 의 `auth` 참조
- **지원 뷰포트**: 모바일(390×844) 우선, PC(1440×900)

## 3. 사전 조건
- 스테이징 환경에 테스트 상품 데이터가 존재
- 장바구니는 비어 있는 상태에서 시작

## 4. 테스트 태스크

### T1. 회원가입 후 첫 로그인
- **목표**: 신규 사용자가 계정을 만들고 로그인한다
- **시작 지점**: 홈 화면(비로그인)
- **성공 기준**: 로그인된 상태로 마이페이지에 내 닉네임이 보인다
- **관찰 포인트**: 본인인증 단계의 이탈 여부, 비밀번호 규칙 안내 명확성

### T2. 상품 검색 후 장바구니 담기
- **목표**: 원하는 카테고리에서 마음에 드는 상품을 찾아 장바구니에 담는다
- **시작 지점**: 홈 화면(로그인됨)
- **성공 기준**: 장바구니에 상품 1개 이상, 수량·옵션이 정확히 표시
- **관찰 포인트**: 검색 정확도, 옵션 선택 UI, 품절 처리

### T3. 쿠폰 적용 후 결제
- **목표**: 보유 쿠폰을 적용해 할인된 금액으로 주문을 완료한다
- **시작 지점**: 장바구니
- **성공 기준**: 주문 완료 화면에 주문번호와 최종 결제금액이 표시되고, 쿠폰 할인이 반영됨
- **관찰 포인트**: 표시 금액과 최종 결제 금액 일치 여부(중요), 쿠폰 적용 위치의 발견 용이성

### T4. 주문 취소/환불 요청
- **목표**: 방금 한 주문을 취소한다
- **시작 지점**: 주문 내역
- **성공 기준**: 취소 접수 확인 메시지가 표시됨
- **관찰 포인트**: 환불 정책 안내, 취소 가능 여부 명확성
